## 第〇部分：系统到底是干什么的

这是一条**脑电（EEG）实验流水线**：

1. 被试戴脑电帽，看屏幕上的第一人称 3D 小游戏（桌上有个杯子）
2. 屏幕提示"想象左手抓杯子"或"想象右手抓杯子"，被试脑内做动作、手不动
3. 电脑同时干四件事：
   - **渲染游戏**（Three.js 网页）
   - **以 250 Hz 记录 8 个电极的电压**（OpenBCI Cyton 放大器 + BrainFlow 驱动）
   - **在时间轴上打标签**（"此刻开始想象左手"——events.jsonl + LSL 标记）
   - **结束后切块训练分类模型**（分辨 Left/Right/Rest）

**核心矛盾**：画面是给人看的，数据是给模型用的。画面卡一下无妨，但"哪个毫秒开始想象左手"这个标签必须精确——模型靠"标签时间点 + 那段脑电"学习，标签漂了训练数据全废。整个方案的一切设计都围绕这个矛盾。

**一个试次（trial）的一生（OpenBMI-Align v1）**：**专用 Rest 4s**（`rest_start`–`rest_end`，计分用静息段）→ **prep 2s**（准备，不算 Rest）→ **Cue = MI 起点**（无额外 Cue 展示秒）→ **MI 固定 4s** → **ITI 3s**。模型学习窗主要是 MI 段 3s/hop100 滑窗；Rest 类来自专用 Rest 片段，不是「Cue 前把 prep 算进去的 4s」。整个系统是一台「高精度打点 + 采数 +（采后）微调」的机器。

## 第一部分：整体架构设计

### 1.1 为什么需要分层

现状：代码挤在几个大文件里（`orchestrator.py` 114KB 干六种活：HTTP 服务、WS 路由、会话编排、微调调度、切窗触发、仿真 campaign）。

**类比**：一家餐厅里经理既点单、又炒菜、又进货、还改菜单——能跑，但任何一处出错互相牵连，想换菜单（换电脑配置）就得让经理停业重学。分层 = 重新划岗：**每人只干一类事，只能向下一层要东西，禁止反向指挥**。

### 1.2 七层职责（从下往上）

| 层 | 名字 | 职责 | 类比 | 不做什么 |
|----|------|------|------|----------|
| L1 | core/ | 原子写、常量、路径解析、日志、通道序定义 | 中央仓库（干净餐具与度量衡） | 不依赖任何人 |
| L2 | runtime/ | 板卡启停、内存缓冲、WS 桥、LSL 流 | 仓库与采购 | 不知道"实验"是什么 |
| L2 | pipeline/ | 切窗、滤波、微调、评估（只碰落盘数据） | 中央厨房流水线 | 不碰实时流 |
| L3 | domain/ | 试次时序、状态机、对齐校验、在线推理 | 后厨工位 | 不关心 COM 口是几 |
| L4 | session/ | 会话生命周期：建目录、写 meta、推进试次、中止 | 厨师长 | 不碰设备细节 |
| L5 | orchestrator/ | 纯调度：消息路由 → 查表转发 | 经理 | 不做业务计算 |
| L6 | tools/ | CLI 入口 ≤80 行：参数→调用→退出码 | 收银台 | 零业务逻辑 |

横切层 **L0 config**（菜单）：机位配置（COM/环境）/ 范式配置（时序/通道）/ 会话快照（本场参数）三分。

### 1.3 两条流（理解方案的钥匙）

- **数据流（宽带）**：电极 → BoardSource → EEGBus → 四订阅者（落盘 / 在线推理 / 前端波形 / 质量监控）
- **控制流（窄带）**：状态机 → 事件（events.jsonl + LSL marker）→ WebSocket → 前端

**协作三规则**（用 import-linter 工具强制进 CI）：
1. 只准上层 import 下层（禁止反向、禁止跳层）
2. core 零本地依赖（谁都能用它，它谁也不用）
3. tools 薄壳不含业务

**为什么通道序定义要放 core**：依赖扫描发现 offline/acquisition 三个文件为了拿"通道顺序"被迫反向 import experiment（共 10 处外部引用）——共享概念被锁在高层，是反向依赖的总根源。

## 第二部分：技术实现细节

### 2.1 原子写（atomic write）

- **问题**：`f.write()` 写一半断电 → 半个文件。meta.json 烂了下季启动失败；微调权重烂了数小时训练白费。
- **原理**：先写 `xxx.tmp`，写完 `os.replace(tmp, 目标)`。`replace` 是操作系统级原子操作——磁盘上要么完整旧版要么完整新版，无中间态。
- **类比**：不在黑板上擦旧写新（中途停电=黑板空白），而是草稿纸写好、一秒挂墙。

### 2.2 EEGBus 单总线（发布-订阅）

- **问题**：现状 EEG 被"落盘"与"在线推理"两路各自拉流，互不知晓健康状态。fnz 实验中落盘 99 秒就断了，推理那路还在拿旧数据算。
- **原理**：全系统只建一个内存环形缓冲（EEGBus），采集线程只写它；落盘/推理/前端/质量都是订阅者。
- **类比**：从"每家自己打井"改成"小区统一供水"——停水时物业第一时间知道所有人家都停了（健康状态共享）。

### 2.3 看门狗（watchdog）+ stale 标记

- **问题**：断流后推理对旧数据反复计算，输出恒定 `[0.71,0.22,0.065]`，被误判为"模型塌缩"（fnz 诊断的真实陷阱）。
- **原理**：EEGBus 记录最后样本时间，`now - last > 2s` 报警暂停（L2），`>5s` 中止（L3）。推理结果打 `stale=true/false`，下游能区分"模型真这么想"和"过期数据算的"。
- **背景**：watchdog 是嵌入式经典术语——狗定期被喂（数据到来），喂不到就吠（报警）。

### 2.4 权威计时 + 同源时钟

- **问题**：标签要毫秒精度；浏览器有 GC、掉帧，自己掐表会漂。
- **原理**：只有 Python 控制器定义"现在几点"（LSL `local_clock()`，本机所有进程共享的高精度时钟）；前端收到指令只渲染。写 events 与推 LSL 标记必须用**同一次**取的时钟值（现状有代码取了两次，差零点几毫秒）。
- **类比**：裁判掐表记成绩；运动员自己戴表记的不算数。

### 2.5 配置三分法 + 解析链

- **问题**：`operator_defaults.json` 写着 `D:\MI\...`、`COM5`——换机即报错（"粘机"首恶）。
- **原理**：配置按"换机要不要动"分三类；读取按优先级链 **环境变量 > 机位文件 > 默认值**（类比 CSS 优先级：内联 > id > 标签）。代码禁止出现盘符/COM 字面量（CI 正则检查）；落盘只写相对路径，读取时 `resolve()` 还原。

### 2.6 BoardSource 接口（策略模式）+ dispatch table

- **BoardSource**：定义"能 start/stop/health/meta 的东西"接口；真机 Cyton / 合成板 / BCI2a 回放各自实现，调用方无感。类比：**USB 口**——插什么硬件电脑不关心。直接落实《换机文档》"真机与仿真共享同一套工具链"。
- **dispatch table**：17 个 `if msg.type=='xxx'` 改成字典查表 `handlers[msg.type](msg)`。新增消息类型只加一行，主函数不改（开闭原则：对扩展开放、对修改关闭）。

### 2.7 数据格式设计

- `X.npy` 形状 `(N,1,8,750)`：N 样本 × 1 × 8 电极 × 750 时间点（3s×250Hz）。
- `meta.json` 强制 `windowing_version` 字段：fnz 发现项目里有 **5 份切窗实现**（通道序/窗长/基线各不相同），模型跨管道使用会静默出错（heldout 0.78 vs 0.50 的实证差距）。给切窗协议打版本号 = 给科学数据贴"配方标签"，任何结果可溯源。

## 第三部分：整体规划思路

### 3.1 设计目标优先级

1. **数据正确性**（最高）——科学实验，错一个标签整场白采
2. **换机零改码**——《换机文档》核心诉求
3. **可维护性**——消重复、解耦合

正确性 > 便利性，所以"改训练数据语义"的切窗归一虽然收益大，被排最后且强制旧数据回归验证。

### 3.2 排期（W1-W6）的权衡逻辑

按 **风险 × 收益** 排，不按模块重要性排：

| 阶段 | 内容 | 为什么排这里 |
|------|------|--------------|
| W1 | core/ 落地 | 风险最低（挪文件+改 import）、收益立现 |
| W2 | EEGBus + 看门狗 | 中风险，但堵住刚发生的真实事故 |
| W3 | Preflight + 机位模板 | 低风险纯新增，换机当天可用 |
| W4 | FT 下沉 pipeline | 中风险，顺带修"先覆盖权重再门控"隐患 |
| W5 | 切窗归一 | **最高风险**（改训练数据语义）→ 放最后 + syj0828 回归 + 实验侧先定协议 |
| W6 | orchestrator 瘦身 | 纯重构不改行为，smoke 脚本兜底 |

**渐进迁移 vs 推倒重写**：选渐进——系统正在产数据，推倒=停实验；每步独立提交可回滚，旧位置留兼容垫片。

**冻结清单的理由**（不改 session_v3 / 前端 / FT 超参）：①正在工作且验证昂贵；②《换机文档》明令；③用接口隔离（BoardSource、SessionRunner）让新代码**包裹**旧逻辑而非重写——绞杀者模式（新结构长在外面慢慢替代，不拆房重建）。

### 3.3 与需求文档的对应

方案开头有需求追踪矩阵：《换机文档》每个功能点（defaults 相对化、机位模板、环境变量覆盖、check_deps 增强、真机/仿真共享工具链…）都映射到方案章节，保证"设计无遗漏、需求有着落"。

## 第四部分：优点与潜在局限

### 优点

1. **问题驱动**：每个设计对应一个实锤 bug（断流→看门狗；5 套切窗→windowing_version；绝对路径→解析链），不是为架构而架构
2. **可回滚**：六步独立提交，任何一步可退回
3. **护栏自动化**：依赖方向 import-linter 进 CI，"人不自觉机器自觉"
4. **可移植性优先级正确**：W1-W3 即达成换机零改码目标，与高风险重构解耦

### 局限与风险

1. **迁移期双份代码**：兼容垫片 = 新旧并存，过渡期维护成本上升，必须限时删垫片
2. **EEGBus 是单点**：总线挂了所有订阅者一起挂；看门狗+收尾协议缓解，单点本质未消除（可选缓解：总线双实例热备，成本高，当前规模不值得）
3. **W5 依赖实验决策**：切窗"哪个是对的"需实验侧拍板，工程无法单方面定
4. **对项目规模可能偏重**：7 层+CI 对 1-2 人团队有仪式感成本；合理裁剪 = W1-W3 必做、W6 可缓
5. **前端小修补触碰冻结区**：重连策略等改动在冻结文件内，需谨慎回归
6. **文档同步成本**：事件字典/WS 协议与代码同 PR 更新是纪律要求，靠单测比对兜底，仍需人守
