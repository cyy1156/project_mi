## 1. 致命

### C1 · FT/小考判定窗时间错位 + 环形缓冲覆盖
- `experiment/session_v2.py:238-244` `_prep_window`：`tail = buf.window_ending_at(local_clock(), 12*250)` 取的是**收集时刻**（整轮结束后）的缓冲尾段，`pre.process(tail)` 后用之；按 `mi_t+t_rel` 取到的正确原始窗 `w_raw` 仅在尾段取不到时兜底。
- 叠加 `experiment/inference_v2.py:28` `RingBuffer(capacity_s=15.0)`：`collect_trial_windows` 在整轮（18 试次 ×13s ≈ 4 min）结束后才调用，此时除最后 ~1 个试次外，所有判定窗早已被环形缓冲覆盖 → `window_ending_at(mi_t+t_rel)` 返回 `None`（`inference_v2.py:82` `start < 0`）。
- 后果：**生产会话的微调与小考数据整体失真**——标定轮 `RoundController` 因 `len(store.windows) < 18` 大概率从不触发；游戏轮只拿得到最后一个试次的少量窗。在线判定本身（`judge()` 在档点时刻被调用）不受影响，此缺陷只在「落库供训练/评估」路径。
- 方向：判定时在线缓存已处理窗（`judge` 已算出），或每试次结束立即抽窗（≤13s，在 15s 容量内）。

### C2 · v2 会话 auto_phase4 必然失败
- `experiment/orchestrator.py:845-859` + `experiment/session_layout.py:12-19`：`finalize_session_layout` 只按 v1 六节点（adapt/learn×3/gate/acquire）切 `by_phase/*/eeg.csv`；v2 事件流（`session_v2`/`trial_v2`）**不发** `phase_start/phase_end` → 六节点全 `None` → `by_phase` 无 `eeg.csv` → `offline/phase4_v2.py:33-48` `load_eeg` 抛 `RuntimeError`。
- 佐证：`data/sessions` 16 个会话全部 `phase_mode=phase2_full`，全仓**无一份** `phase4_v2/` 产出。D5 自动双管道在 v2 模式下从未真正工作过。

## 2. 高

### H1 · pilot preset 必然降级（L1 冒烟测不到真推理）
- `config/v2_session.pilot.yaml` 无 `s3_task_ckpt/s3_three_ckpt`；`experiment/v2_config.py:94-116` `load_yaml` 只读所给文件、用 dataclass 默认（空串）兜底、**从不合并 prod yaml** → `session_v2.py:44-47` 路径检查失败 → 永远落入「流程演练模式」。
- 未被测试暴露的原因：`self_test_d8.py` 对 pilot 只断言轮数，降级冒烟恰好断言 `degraded is True`。

### H2 · rest 试次丢出标定切窗池
- `offline/phase4_v2.py:81-89`：rest 入池要求 `t_rest_start` 列；但 `trial_v2` 对 rest 试次同样发 `mi_start/mi_end`、从不发 `rest_start` → `alignment.py:60-71` 填不出该列 → **每轮 6/18 的静息试次全部静默丢弃**，标定池无 0 类、`y_task` 无负样本。

### H3 · 回放池未接线，15% 回放静默蒸发
- `session_v2.py:320-329` 构造 `IncrementalFinetuner` 不传 `replay_pool`；`adapt_engine/ft.py:126` `if self.replay_pool is not None` 静默跳过（无日志无事件）。`REPLAY_RATIO=0.15` 是冻结常量（系统设计 §3.6），当前所有轮间/熔断 FT 实际无回放。

### H4 · 无效试次进 FT/小考；缺窗时跨轮混入
- `session_v2.collect_trial_windows`（212-236）不按 `store.valid_trials` 过滤 → 标定前 12（FT）与后 6（小考）均可混入无效试次。违反 `v2_upgrade_plan` §7.6「无效 trial 不进 FT」（仅熔断路径 266-279 正确过滤）。
- `session_v2.py:347-348` 用累计量判断再取 `sorted(keys)[-18:]`：某轮缺窗时把**上一轮已消耗试次**混入——落后 6 位则 `QuizStore.add` 抛重复入库 `ValueError`（`adapt_engine/quiz.py:38-39`）崩会话；游戏轮 `[-16:]`（393 行）同理可把**小考试次拉进游戏 FT**。

### H5 · DriftGuard 实现完整但零接线
- `adapt_engine/drift.py`（含逐位回滚/二档冻结单测）全仓无调用；`session_v2.py:328` 设了 `ckpt_dir` 但无人调用 `save_checkpoint`（目录恒空）；`drift_stats`（336/402 行）只是训练记录，命名误导。

### H6 · 游戏轮微调粒度 = 轮级 —— **已改判：无需修复（2026-08-24）**
- `session_v2.py:392-401`：整轮 16 试次结束后一次 `train_round`。
- 原判依据为定稿 v3.0 的 E2（组级）；定稿 v3.1 以 v2 为标准（D2=B 轮级批量冻结）后，**当前实现即正确**，不改代码；比赛 3.3 分组条文按「组 = 排程平衡单位 + 轮界批量更新」在提交文本中对齐（见定稿 §6.1/§11）。
