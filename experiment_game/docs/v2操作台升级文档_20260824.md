## 2. v2 现状盘点（差距来源）

- **Setup**：S5/S6 两个 fieldset 带 `phase2-only`，v2 模式下被隐藏（`operator.js:131-132`）；v2 参数**完全不可在 UI 编辑**，提示指向 `config/v2_session.yaml`（operator.html:79）；
- **Run**：R1/R3/R5 共享可用；R2 步骤条仍是 v1 词（adapt/learn/…）；R4 只有 gate 盒 + 引导确认，**缺轮进度、D8 实时 Score、轮间 FT/漂移状态**；
- **Summary**：U2 仍是 v1 切窗参数；v2 三管道（phase4_v2 / _game / pooled + merged）收工自动跑（orchestrator:841），但**页面不展示结果**；U1 徽章无 v2 验收口径；
- **已存在的接入点（好消息）**：
  - orchestrator:846 已支持 `exp.get("v2_config_path")` 自定义配置路径；
  - orchestrator:772 已把 `v2_config` 写入 session.meta.json；
  - `V2Config.verify()`（v2_config.py:107）已有范围校验，可直接复用做 UI 越界拦截；
  - seed 目前只接 v1（orchestrator:531），**v2 未接**——需补。

## 4. 数据流与接入设计

```
Setup UI（v2 字段）
  → ws config 消息新增 v2_overrides: {…}（operator.js:231 收集处扩展）
  → orchestrator v2 启动（L741+）：V2Config.load_yaml() 后 apply_overrides(v2_overrides)
  → V2Config.verify() 范围校验（越界拒绝并回传错误，复用 L107）
  → 生效配置整份快照入 session.meta.json（v2_config_effective；L772 处扩展）
```

- **参数优先级**：UI overrides > yaml 推荐值；yaml 仍是唯一推荐源与默认值来源；
- 备选接入（不推荐）：UI 写临时 yaml + 传 `v2_config_path`（L846 已支持）——会污染 config 目录，overrides 方案更干净；
- 冻结锁（G5）在 orchestrator 侧**双保险**：收到 `protocol_locked=true` 时忽略非常量白名单的 overrides。

## 6. 验收标准

| # | 标准 |
|---|------|
| A1 | v2 模式 Setup 全部 fieldset 可见；调试模式下字段可编辑且值能 round-trip 进 meta（v2_config_effective 与 UI 一致） |
| A2 | 采集模式下 G2/G3 字段 disabled + 锁定标识；orchestrator 忽略非白名单 overrides |
| A3 | 时序预设/时间轴/合计正确：标准 2/2/6/3 → 单 trial ≤13s；预计时长与任务书 60–75 min 口径一致 |
| A4 | 越界值（如 gate=0.9、lr=1）被 verify() 拦截并红字提示，无法开始实验 |
| A5 | Run 视图轮次/Score/FT 状态实时正确，与 events 落盘逐档记录对账一致 |
| A6 | Summary 三管道窗数与落盘文件数一致；验收徽章对 §7 四门判定正确 |
| A7 | 远程监控端（方案 B）看到与本机完全一致的 v2 UI |
| A8 | v1 模式全功能回归无变化（S5/S6、切窗、步骤条原样） |

## 7. 边界说明

- 冻结常量在**采集日**不可改是流程纪律（yaml 注释已声明）；G5 把纪律变成 UI 硬约束，防止操作者手滑——这是本升级对 20 人战役的直接价值；
- 调试跳过（G1）仅冒烟测试用，正式采集勾选即视为协议偏离，meta 留痕可追溯；
- 本升级不改变任何算法口径（D1–D8、三管道、merge 均不动），只把"已存在的参数"从 yaml 搬到 UI 并加监控。
