# 换机最小运行指南 · 与可移植性重构建议

> 日期：2026-08-28  
> 范围：`experiment_game` 采集 / 诱导页游戏 / 操作台 / 被试在线微调（FT）  
> 目标：在**另一台笔记本**上以**尽量不改业务代码**的方式跑通；并登记后续小重构优先级。  
> 状态：**建议文档**（本文不代替改代码；落地时按清单操作即可）

---

## 0. 一句话结论

- **换机默认：不改 `session_v3` / `operator.js` / FT 算法。**  
- 只处理三件事：**同步代码、拷必备大文件、为本机配 Python + `machines/<机名>/`，并清掉带绝对路径的 `operator_defaults.json`。**  
- 盘符、用户名、有无独显、COM 口号 → 全部用**配置 / 启动脚本 / UI**消化，不要写进游戏逻辑。

---

## 1. 架构里哪些已经「可移植」

| 模块 | 现状 | 换机要不要改代码 |
|------|------|------------------|
| 仓库根探测 | `Path(__file__).parents[…]` → `_REPO` | 否 |
| FT 底座权重默认 | 相对 `_REPO` 的 `run_20260822_094942/.../best_*.pt` | 否（路径结构保持不变即可） |
| OpenBMI replay | 相对 `_REPO` 的 `preprocess_lab/out/openbmi_3s_hop100_t0` | 否 |
| FT `device` | `cuda if available else cpu` | 否 |
| 被试目录 | `experiment_game/data/subjects/{id}/…` | 否 |
| 仿真目录 | `experiment_game/data/sim_subjects/{A0X}/…` | 否 |
| 机位入口 | `experiment_game/machines/<机名>/` | **复制改配置**，不改业务 |

真正「粘在某一台电脑上」的，多半是：

1. `experiment_game/config/operator_defaults.json` 里的 **`D:\MI\…` 绝对路径**、**COM 口**、某次本地 `ft_runs`  
2. `machines/*/machine.json` / `_resolve_python.bat` 里的 **用户名与 conda 路径**  
3. 未同步的大文件（T0 权重、OpenBMI `_t0` npy、可选 `DATA/bci2a`）

## 2. 新笔记本最小落地清单（推荐顺序）

### 2.1 同步代码

```text
git clone <仓库>   或   git pull
```

仓库可放在任意盘任意目录，例如：

- `C:\MI`
- `D:\work\project_mi`

**不要假设**永远是 `D:\MI`。

### 2.2 拷贝「跑通游戏 + 在线 FT」必需大文件

在**相对仓库根**的相同子路径下放置（从本机或网盘拷贝）：

| 优先级 | 相对路径 | 用途 |
|--------|----------|------|
| P0 | `code/train_lab/out/5070_baseline_openbmi_3s_hop100_accpaper/shallow_openbmi_3s_hop100_balbatch_accpaper/openbmi_3s_hop100/run_20260822_094942/three/fold0/best_three.pt` | 在线推理 / FT 起点 |
| P0 | 同上目录树 `…/task/fold0/best_task.pt` | task 头 |
| P0（开 replay 时） | `code/preprocess_lab/out/openbmi_3s_hop100_t0/`（至少含 `openbmi_X.npy`、`openbmi_y_three.npy`、`openbmi_subjects.npy`） | FT B2 replay；`openbmi_X.npy` 约数 GB |
| P1（仅仿真） | `DATA/bci2a/A01T.mat` … `A09T.mat` | BCI2a 仿真回放 / 仿真 FT |
| P2（可选） | 旧机 `experiment_game/data/subjects/` 或 `sim_subjects/` 下的 session | 拿旧数据做 FT，非启动必需 |

> 备选：若没有 `_t0` 目录，可放全量 `code/preprocess_lab/out/openbmi_3s_hop100/`（代码会按 T0 被试集合过滤）。  
> 临时验证可用操作台关掉 replay / CLI `--no-replay`，但**正式被试 FT 仍建议 B2 + 0.10**。

### 2.3 安装 Python 环境

任选其一（推荐 conda，与现网一致）：

```powershell
conda create -n cyy python=3.11 -y
conda activate cyy
# 按新机 CUDA 情况安装 torch，再装：
pip install braindecode numpy pandas scipy websockets pyyaml
# 采集另需：brainflow、pylsl（及设备厂商驱动）
```

自检：

```powershell
python -c "import torch, braindecode, numpy, pandas; print('torch', torch.__version__, 'cuda', torch.cuda.is_available())"
```

- 有独显且装好 CUDA 版 torch → FT / 推理自动走 GPU  
- 无独显 → 自动 CPU，**不用改代码**，只是更慢  

### 2.4 新建本机机位目录（复制，勿改共享根 bat）

```text
experiment_game/machines/5070_laptop/     ← 模板
                    ↓ 复制
experiment_game/machines/<新机名>/
```

至少改：

1. **`machine.json`**
   - `machine_id` / `hostname` / `gpu`
   - `repo_root` → 新机实际仓库绝对路径  
   - `python.conda_env` / `example_exe` → 新机 conda 路径  

2. **`_resolve_python.bat`**
   - 去掉或改掉写死的 `C:\Users\yy\…`  
   - 保留：`%USERPROFILE%\.conda\envs\<环境名%\python.exe` 一类可移植探测  

3. **`README.md`**  
   - 写清：本机盘符、环境名、用本目录哪些 bat  

**禁止**：为迁就新机去改 `experiment_game/open_operator.bat` 等**共享根入口**（那是给其它机位 / `.venv` 用的）。

启动请用：

| 用途 | 入口 |
|------|------|
| 依赖检查 | `machines/<新机名>/check_deps.bat` |
| 操作台 | `machines/<新机名>/open_operator.bat` |
| 诱导页 / 游戏 | `machines/<新机名>/open_induction.bat` 或 `打开诱导页.bat` |
| 局域网（平板浏览器） | `open_operator_lan.bat` |

### 2.5 清掉粘本机的 UI 记忆

删除或改名：

```text
experiment_game/config/operator_defaults.json
```

该文件常含：

- `save_root: D:\MI\…`  
- `campaign_manifest: D:\MI\…`  
- `serial_port: COM5`  
- 指向某次本地 `ft_runs/…` 的权重  

新机第一次打开操作台会重新生成。采集前在 UI 里选对本机 **COM / BrainFlow 板型**。

### 2.6 跑通冒烟

1. `check_deps` 全绿（至少 torch / websockets / 可选 pylsl）  
2. 开操作台 + 诱导页  
3. **登录被试**（真机）→ 确认 `save_root` 落在  
   `experiment_game/data/subjects/{id}/sessions`  
4. 干跑一场（可先关采集做 UI 流程，或开采集做真 EEG）  
5. 勾选 session → 微调 → 看 `ft_runs` 是否写出 → 按需 promote 到 `current`  

CLI 不经 UI 验 FT：

```powershell
conda activate cyy
cd <仓库根>
python experiment_game/tools/ft_subject_from_v3.py --session <某session目录> --out-dir <输出目录>
```

## 3. 「最小修改」原则：什么改、什么不改

### 3.1 换机时不要改

- `experiment_game/experiment/session_v3.py`、`trial_v2.py`  
- `experiment_game/web/js/operator.js`、`main.js`、`scene.js`（游戏/诱导）  
- `code/adapt_engine/ft.py` 训练超参（除非做实验，不是换机）  
- 为每台电脑维护第二套网页或第二套范式时序  

### 3.2 换机时只动这些

| 层级 | 内容 |
|------|------|
| 数据 | T0 权重、OpenBMI `_t0`、可选 mat / 旧 session |
| 环境 | conda / venv + 依赖 |
| 机位 | `machines/<新机名>/` |
| 本机状态 | 删除 `operator_defaults.json`；UI 改 COM |
| 网络 | 本机用 127.0.0.1；跨设备浏览器用 LAN bat + IP |

### 3.3 只有这些情况才值得改「一点」代码/常量

| 情况 | 建议 |
|------|------|
| 权重死活不能放在默认相对路径 | CLI `--task-ckpt` / `--three-ckpt`，或以后加环境变量；仍避免改游戏 |
| Replay 盘空间不够，放到外置盘 | 符号链接到 `preprocess_lab/out/openbmi_3s_hop100_t0`，或以后支持 `OPENBMI_ROOT` 环境变量 |
| 操作台要强制选 CPU | 给 `finetune_start` 加可选 `device`（小改 orchestrator + UI） |

## 4. 可移植性重构建议（优先序 · 待你确认后再改代码）

以下按 **收益 / 改动量** 排序，供后续小 PR，**不是现在必须做的**。

### P0 · 立刻能减少踩坑（改动小）

1. **`operator_defaults.json` 不进版本库**  
   - `.gitignore` 忽略该文件  
   - 提交 `operator_defaults.example.json`（相对路径示例、无本机 COM）  
   - 文档写明：新机删除本地 defaults  

2. **写入 defaults 时优先相对 `repo_root` 的 `save_root`**  
   - 例如 `experiment_game/data/subjects/{id}/sessions`  
   - 避免再把 `D:\MI\…` 写回磁盘  

3. **换机自检脚本增强**（可扩现有 `check_deps.py`）  
   - 检查：`DEFAULT_THREE` / `DEFAULT_TASK` 是否存在  
   - 检查：`openbmi_3s_hop100_t0/openbmi_X.npy` 是否存在  
   - 打印：`repo_root`、`cuda`、建议的 `save_root`  
   - 失败时给出「该拷哪个文件夹」的中文提示  

### P1 · 机位体验（中等）

4. **机位模板目录** `machines/_template/`  
   - 空白 `machine.json`、无硬编码用户名的 `_resolve_python.bat`  
   - README 复制清单与本节 §2 对齐  

5. **`_resolve_python.bat` 去掉写死 `C:\Users\yy\…`**  
   - 只保留 `%USERPROFILE%` / `CONDA_PREFIX` / `where python`  

6. **文档入口**  
   - 在 `machines/README.md` 顶部链到本文  
   - 在 `仿真板块_BCI2a_v3_*.md` / 被试登录方案中各加一行「换机见本文」  

### P2 · 可选增强（有需要再做）

7. 环境变量覆盖：  
   - `MI_REPO_ROOT`（极少需要）  
   - `MI_OPENBMI_REPLAY_ROOT`  
   - `MI_T0_THREE_CKPT` / `MI_T0_TASK_CKPT`  

8. 操作台 FT 高级项增加 **device: auto|cuda|cpu**（默认 auto）  

9. 首次启动向导：缺权重 / 缺 replay 时弹窗说明，而不是 FT 中途 `RuntimeError`  

### 明确不建议的重构

- 为每台笔记本 fork 游戏前端  
- 把盘符写进 `session_v3` / 评分逻辑  
- 把 FT 默认 epoch/lr 按「机器型号」分支（实验策略与机位正交）

## 5. 真机采集 vs 仿真：换机差异

| | 真机被试 | BCI2a 仿真 |
|--|----------|------------|
| 必需大文件 | T0 权重 +（建议）replay `_t0` | 同上 + `DATA/bci2a/*.mat` |
| 硬件 | 放大器 / COM / BrainFlow | 无 |
| 登录 | 普通被试 ID | 仿真被试 `A01`… |
| FT 切窗 | `openbmi_align`（LSL cue） | `sim_mat_cue`（mat cue） |
| Leave-Next | 按 session 勾选 / 以后 UI | Campaign + Leave-Next 勾选 |

两边**共享**同一套 operator / FT 工具链；差别只在数据源与登录模式。

## 6. 故障速查

| 现象 | 优先检查 |
|------|----------|
| `No module named torch` / `braindecode` | 是否用了机位 bat / 是否激活错环境 |
| FT：`无法构建 T0 replay 池` | `_t0` 或全量 OpenBMI out 是否在约定相对路径 |
| FT / 推理：找不到 `best_three.pt` | `run_20260822_094942` 树是否拷全 |
| 保存路径在旧盘 `D:\MI` 报错 | 删 `operator_defaults.json`；重新登录被试 |
| 采集连不上 | COM 号、驱动、BrainFlow 板型；与 FT 无关 |
| 诱导页空白 / WS 断 | 操作台是否已启动；LAN 时 IP/防火墙；硬刷新缓存（`operator.js?v=…`） |
| FT 很慢 | 无 CUDA 属正常；勿因此改业务代码 |
