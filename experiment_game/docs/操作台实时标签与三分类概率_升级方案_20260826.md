# 操作台实时标签与三分类概率 · 升级方案

> 日期：2026-08-26  
> 状态：**已实施**（v2/v3 面板 · 百分比条 · events.jsonl 写入）  
> 范围：操作台（后台）实时显示「当前正式标签」+「模型三分类概率」  
> 相关：`inference_v2.py` · `trial_v2.py` · `session_v2.py` / `session_v3.py` · `web/js/operator.js` · `web/operator.html`  
> 代码：`experiment/class_labels.py` · `trial_v2.py` · `session_v2.py` / `session_v3.py` · `web/operator.html` · `web/css/operator.css` · `web/js/operator.js`

---

## 1. 目标

在 **操作台（后台）** 于 MI 判定过程中实时看到：

| 项 | 含义 | 示例 |
|----|------|------|
| **正式标签** | 当前试次协议真值（cue 规定的类别） | `Rest` / `Left` / `Right`（0/1/2） |
| **三分类概率** | 模型对当前 3s 窗的 three 头输出 | `Rest 0.12 · Left 0.71 · Right 0.17` |
| **（附带）预测类** | `argmax(p_three)` 或串行门控后的 `pred` | `Left ✓/✗` 相对正式标签 |

**不做**：被试屏展示概率/标签数字；不改 D8 计分公式；不改模型结构。

---

## 2. 现状与缺口

### 2.1 已有

| 层 | 现状 |
|----|------|
| 推理 | `InferenceService.judge` 已返回 `pred` / `p_three` / `p_task` / `margin` / `gated` |
| 协议标签 | `TrialContextV2.label` ∈ {0,1,2}；`v2_stage.ctx.label` 已广播 |
| 操作台 | `st-label` 显示 **数字** `0/1/2`，无中文/英文类名 |
| v3 试次结束卡 | 试次结束后可看 `primary_judge` + `p_three`（**非逐窗实时**） |
| D8 Score | 操作台已有实时 score 条 |

### 2.2 缺口

1. **正式标签可读性差**：仅数字，操作员难一眼对齐「当前该想哪边」。  
2. **逐窗概率未上操作台**：`judge` 通知里虽可能带 `p_three`，但 `operator.js` **未渲染**；且 `events.jsonl` 的 `judge` 落盘 **未写** `p_three`（`trial_v2._emit` 只写了 `pred/p_max/gated/score`）。  
3. **v2/v3 不统一**：v3 结束卡有概率；v2 标定/游戏轮缺少同等实时面板。

---

## 3. 约定（冻结）

### 3.1 类别映射（与现网一致）

| id | 正式名（显示） | 简称 |
|----|----------------|------|
| 0 | Rest | 静息 |
| 1 | Left | 左手 MI |
| 2 | Right | 右手 MI |

`p_three` 顺序固定为 **`[P(Rest), P(Left), P(Right)]`**，与 three 头输出一致。

### 3.2 显示时机

| 阶段 | 正式标签 | 三分类概率 |
|------|----------|------------|
| `prep` / `cue` | 显示（cue 已定） | `—`（尚未判定） |
| `mi` / 每次 `judge` | 保持 | **刷新**（该判定点最新窗） |
| `signal_bad` | 保持 | 显示「信号差 / 未推理」 |
| `iti` / `trial_end` | 可保留末次值至下一试次 `trial_start` 清空 | 同左 |

刷新频率：与现网 `judgment_step_s`（默认 0.6s）一致，**不另开推理周期**。

### 3.3 用哪个 pred？

当前 `task_p_on: 0.0`，串行门控关闭 → `pred == argmax(p_three)`。

方案约定：

- 面板同时显示：`pred`（门控后）+ 完整 `p_three`  
- 若日后重新打开 `task_p_on`，额外显示 `gated: true` 与 `p_task`（可选二期）

## 4. 消息契约（WS）

沿用现有 `type: "v2_stage"`，在 `stage === "judge"`（及可选 `cue`）时规范字段：

```json
{
  "type": "v2_stage",
  "stage": "judge",
  "ctx": {
    "trial_id": 12,
    "label": 1,
    "label_name": "Left",
    "mode": "game",
    "round": 1
  },
  "data": {
    "t_rel": 3.6,
    "pred": 1,
    "pred_name": "Left",
    "p_three": [0.12, 0.71, 0.17],
    "p_max": 0.71,
    "gated": false,
    "correct": true,
    "score": 2.4,
    "arm_level": 1,
    "cup_grasp": false
  },
  "progress": { "...": "..." },
  "score": 2.4
}
```

约定：

- **`ctx.label` / `ctx.label_name`**：正式标签（真值）  
- **`data.p_three`**：长度 3 的 float 列表；缺省或 `null` = 本 tick 未推理  
- **`data.correct`**：`pred == label`（Rest 试次同样可比）  
- 被试屏 `v2_bridge.js`：**忽略** `p_three` / `label_name`（仅操作台用）

`cue` 阶段可只发 `label` / `label_name`，便于 MI 开始前就亮出正式标签。

## 7. 边界与风险

| 风险 | 处理 |
|------|------|
| `p_three` 为 numpy / 不可 JSON | 沿用现有 `_ser` / list(float) 转换 |
| 无模型降级（infer=None） | 标签仍显示；概率显示「无模型」 |
| 带宽 | 每 0.6s 多 3 个 float，可忽略 |
| 操作员误把概率给被试看 | 仅挂在 `operator.html`；诱导页不接 |
