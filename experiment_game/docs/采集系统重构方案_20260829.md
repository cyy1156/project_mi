## 1. 系统总体架构设计

### 1.1 分层结构（7 层 + 1 横切）

```text
┌────────────────────────────────────────────────────────────────┐
│ L6  tools/            薄 CLI（≤80 行/个）：argparse + 调用 + 退出码 │
├────────────────────────────────────────────────────────────────┤
│ L5  orchestrator/     纯调度：HTTP + WS 路由 → dispatch table     │
├────────────────────────────────────────────────────────────────┤
│ L4  session/          SessionRunner 基类；v2/v3/v4 只写差异        │
├────────────────────────────────────────────────────────────────┤
│ L3  domain/           timing · trial_sm · alignment · inference   │
│                       · signal_quality · class_labels           │
├──────────────────────────────┬─────────────────────────────────┤
│ L2  pipeline/  离线流水线       │ L2  runtime/  运行时              │
│  windowing(唯一)·finetune      │  ring_buffer·markers·events_log  │
│  ·eval_utils·filters          │  ·ws_bridge·http_static·board    │
├──────────────────────────────┴─────────────────────────────────┤
│ L1  core/             零依赖：io(原子写)·constants·logging·paths │
├────────────────────────────────────────────────────────────────┤
│ L0  config（横切）     site/ 机位 · protocol/ 范式 · run_config   │
└────────────────────────────────────────────────────────────────┘
```

**各层职责与"不做什么"：**

| 层 | 职责 | 明确不做 |
|----|------|----------|
| L6 tools | 参数解析、组装调用、进程退出码 | 任何业务逻辑（FT 业务下沉 L2） |
| L5 orchestrator | 消息路由、组件装配、状态广播 | 时序计算、切窗、训练（全部委托下层） |
| L4 session | 会话生命周期：建目录、写 meta、试次编排、abort | 设备细节、模型细节（经 L2/L3 接口） |
| L3 domain | 范式时序、状态机、对齐校验、在线推理、质量判定 | 磁盘路径、串口（经 L1 paths / L2 board） |
| L2 pipeline | 切窗（唯一实现）、滤波、微调、评估 | LSL 实时流（只碰落盘数据） |
| L2 runtime | RingBuffer、LSL outlet/inlet、WS 桥、板卡启停 | 范式语义（不知道什么是 cue） |
| L1 core | 原子写、常量、路径解析、日志 | 任何本地 import |
| L0 config | 三类配置的加载/校验/快照 | 被任何业务硬编码绕过 |

**依赖规则（三条，import-linter 固化）：**
1. 只准上层 import 下层；禁止反向、禁止跳层。
2. `core/` 零本地依赖。
3. `tools/` 薄壳；`session_v3.py`、`web/*.js`、FT 超参**冻结**（《换机文档》§3.1）。

### 1.2 与现状的映射（迁移不推倒）

| 现有模块 | 去向 | 说明 |
|----------|------|------|
| `experiment/channel_layout.py` | `core/` | 解开 offline/acquisition 反向依赖（依赖扫描实证 10 处外部引用） |
| `experiment/orchestrator.py` (114KB) | 拆 `orchestrator/`：`http_routes.py`+`ws_routes.py`+`handlers/{ft,phase4,sim}.py` | `_on_ws_message` 17 分支 if-elif 改 dispatch table |
| `experiment/session_v2/v3/v4*.py` | `session/` + `SessionRunner` 基类 | 建目录/meta/emit/abort 公共化，v2/v3 只留差异 |
| `tools/ft_subject_from_v3.py` (43KB) | `pipeline/finetune.py` + 60 行 CLI 壳 | 解开 experiment→tools 环（依赖扫描实证） |
| `offline/epochs·pipeline·phase4_v2·openbmi_align_cut`（4 套切窗） | `pipeline/windowing.py`（唯一） | fnz 实证双轨制代价：heldout 0.50 vs 0.78 |
| `acquisition/service.py` | `runtime/board.py` + `BoardSource` 抽象 | 真 机/synthetic/replay 同接口（《换机文档》§5） |
| `machines/<机名>/` | 保留 + `_template/` | 唯一允许出现主机名/conda 路径的地方 |

### 1.3 配置体系（可移植性核心）

**配置三分法：**

| 类别 | 位置 | 内容 | 换机 |
|------|------|------|------|
| 机位 site | `machines/<机名>/machine.json` | COM 号、conda 环境、gpu、repo_root | 复制改 |
| 范式 protocol | `config/protocol.yaml` | timing、通道序、场景物品枚举、标签 | 不改 |
| 会话 run_config | 会话目录内（快照） | 本场全部生效参数（含 protocol 快照） | 只读 |

**解析链（所有路径/参数的唯一入口 `core/paths.py` + `core/config.py`）：**

```text
环境变量 MI_*  >  machines/<机名>/machine.json  >  config/protocol.yaml 默认值
```

- 代码中**禁止**出现 `D:\`、`C:\Users\`、`COM5` 字面量（CI 正则检查）。
- 落盘的任何 JSON（defaults、meta、pointer）**只写 repo 相对路径**；读入时经 `core/paths.resolve()` 还原。
- defaults 文件退出版本库 + 提交 example（《换机文档》§4-P0-1）。

**依据**：《换机文档》§0"盘符、用户名、有无独显、COM 口号→全部用配置消化"；现状 `operator_defaults.json` 含 `D:\MI\...` 与 `COM5` 是粘机三大来源之首。

## 2. 现有问题分析 → 改进点与理由

### 2.1 耦合度

**现状**（AST 依赖扫描，详见《架构重构分析报告》§1）：
- 3 处反向依赖：experiment→tools（FT 业务在 CLI）、offline→experiment ×3 与 acquisition→experiment（只为 channel_layout）、experiment↔offline 成环（phase4）。
- orchestrator 114KB，HTTP/WS/会话/FT/phase4/sim 六职合一。

**A1 改进：channel_layout 下沉 core + FT 下沉 pipeline（理由见 §1.2 映射表）。**
三处反向依赖的修复成本合计约 13 个文件的 import 行；做完后 offline/acquisition/pipeline 成为可独立测试的纯库。

### 2.2 数据流转效率

**现状**：
- EEG 落盘走 lsl_connect Recorder（eeg.csv），在线推理另起 RingBuffer 拉流——两条消费路径，无统一背压。
- eeg_frame 每 0.3s 推前端 2.5s 窗（硬编码，`eeg_frame_publisher.py:67-69` 下采样因子 4 未命名）。
- 试次特征每 trial 重开 features.jsonl（`session_v3._finalize_trial:503`）。

**A2 改进：runtime 统一 `EEGBus`（单一 RingBuffer，多订阅者）。**
采集线程只写一次内存环；Recorder 落盘、在线推理、前端 frame 推送、质量监控全部作为**订阅者**挂总线。收益：①消除重复拉流；②订阅者可声明背压策略（丢帧 vs 阻塞）；③断流检测只在总线一处实现（见 §5.2）。
依据：fnz ws07 断流时推理与落盘行为不一致（落盘停了、状态机还在跑），根因是两条消费链各自为政、无共享健康状态。

### 2.3 稳定性

**现状问题（均有实证）：**
- ws07 EEG 断流后无任何告警，推理对陈旧数据输出恒定概率，状态机空跑到 block_gap 被人工中断，eeg.meta.json 缺失。
- 微调先覆盖 `best_*.pt` 再做门控（`ft_subject_from_v3:957-992`）。
- 全项目 ~15 处非原子写；EventLogger/RingBuffer/AcquisitionFacade 无上下文管理器。
- WsBridge 单条非 dict 消息即断连；前端重连 8 次永久放弃。

**A3 改进：三级容错体系（详见 §5）。**
**A4 改进：资源协议 + 原子写统一（core/io）。**
所有持有线程/句柄的类实现 `__enter__/__exit__`；所有落盘走 `atomic_write_text/atomic_torch_save/atomic_np_save`（tmp + `os.replace` + 可选 fsync）。
依据：审查报告 P2 多条 + fnz 诊断 §3.4。

### 2.4 可扩展性

**现状**：v2/v3/v4 三套 session 平行复制（42KB+34KB+…），新范式=再复制一套；事件字典 marker_spec v0.2 未收录 v3 新事件（`prep_start/iti_start/judge/v3_*` 实际在 ws07 events 中大量出现）。

**A5 改进：SessionRunner 基类 + 事件字典升级 v0.3（§4.2）。**
**A6 改进：BoardSource 数据源抽象**——真机 Cyton / synthetic / BCI2a replay 三种来源同一接口（《换机文档》§5"两边共享同一套工具链，差别只在数据源"的直接落地）。

## 3. 数据采集、传输、存储与展示完整流程

### 3.1 端到端流程图

（见本回复内嵌数据流图；文字版如下）

```text
[被试] → Three.js 诱导页 ──WS(8765)──┐
                                     ▼
[放大器]→BrainFlow→OpenBCI_EEG(250Hz×8ch)──→ runtime.EEGBus ──┬→ Recorder → eeg.csv（原子追写+fsync）
                                                              ├→ inference（3s/hop100 滑窗 → three 头 → judge）
                                                              ├→ eeg_frame 订阅 → WS 推操作台波形
                                                              └→ quality 订阅 → 坏导联/坏窗标记
[控制器 session/] ──状态机──→ events.jsonl + LSL Markers（format_payload，t_lsl 同源）
        │                      │
        ├→ WS stage/prompt → 被试屏 + 操作台（只渲染，不计时）
        └─会话结束→ manifest + verify_report → pipeline.windowing → epochs(N,1,8,750)
                     → pipeline.finetune → release_gate → promote current → 下场会话 s3_*_ckpt
```

### 3.2 采集（Acquire）

1. **Preflight**（§5.1）通过后，`runtime/board.py` 按机位配置启板：`BoardSource.start()` → BrainFlow `prepare_session/start_stream`，发布 LSL `OpenBCI_EEG`。
2. **EEGBus** 拉流线程以 250Hz 入环；同时开启**流健康监测**（最后样本时间戳 vs `local_clock()`，阈值 2s 告警 / 5s 暂停，§5.2）。
3. synthetic 与真机仅 `BoardSource` 实现不同，`machines/<机名>/machine.json` 的 `board:` 字段切换——换机/联调零改码。

### 3.3 传输（Transport）

| 通道 | 承载 | 关键规约 |
|------|------|----------|
| LSL `OpenBCI_EEG` | 250Hz×8ch float | 采集侧唯一 EEG 出口（科研工具可旁路订阅） |
| LSL `OpenBCI_Markers` | 事件字符串 | `format_payload()` 唯一生成点；timestamp=events 行 `t_lsl`（同一次 `local_clock()` 取值） |
| WS 8765 | stage/hud/prompt/operator_state/v2_stage… | 控制器权威计时；前端只渲染（冻结原则） |
| WS `eeg_frame` | 0.3s 节流 2.5s 窗 | 节流参数入 protocol.yaml，消除硬编码 |
| WS `client_stats` | 前端→后端 fps/max_gap | 页面 hidden 时标记 `background:true`，防 RAF 降频污染（审查 L21 实测 max_gap 41s 离群） |

**依据**：《换机文档》§3.1 冻结前端；marker_spec"控制器先取 t_lsl 再写 events 并推 marker"——现状 `trial_sm.run_block:222` 绕过 `_emit` 取了两次时钟，属实现 bug，方案要求 marker 时间戳**必须**来自同一次取值（§4.3）。

### 3.4 存储（Persist）

**会话目录（统一到 subjects 双层）：**

```text
data/subjects/{subject_id}/sessions/{subject}_{session}_{YYYYMMDD_HHMMSS}/
  session.meta.json      # 含 protocol 快照 + 机位摘要(board/COM/firmware) + channel_labels
  run_config.json        # 开场生效配置全量快照
  eeg.csv                # lsl_time + 8ch（列序=DEVICE_CHANNEL_LABELS，meta 内声明）
  eeg.csv.meta.json
  events.jsonl           # 行格式见 §4.2
  manifest.json          # 文件清单+行数+sha1（会话收尾写；§5.3 完整性校验依据）
  continuous/  by_phase/  alignment/trial_table.csv  verify_report.json
  v3_segments/  v3_trial_features.jsonl  v3_report.{json,md}
  99_summary/phase4_pointer.json
data/subjects/{subject_id}/models/
  ft_runs/{stamp}/  best_{task,three}.pt · report.md · release_gate.json · meta.json
  current/          → 指向某 ft_run（promote 语义：门控 PASS 才允许）
data/epochs/{会话名}/  X.npy · y_task.npy · y_three.npy · train_* · val_*
```

**规约：**
- 所有 JSON/pt/npy 写入一律 `core/io.atomic_*`（tmp→`os.replace`）；events.jsonl 单行一次 `write` + 行级 flush（半行即坏行的 fnz/审查教训）。
- `data/sessions/`（旧平铺）保留只读兼容，新会话一律落 `data/subjects/{id}/sessions/`（现状已是事实标准，fnz/syj 均在此）——**消除双轨**。
- weights 路径一律 repo 相对（如 `code/train_lab/out/.../best_three.pt`）；`--task-ckpt/--three-ckpt` 与 `MI_T0_*_CKPT` 覆盖（《换机文档》§3.3）。
- FT 权重：先写 `best_*.pt.tmp`，`release_gate PASS` 后 `os.replace`；FAIL 保留上一版并在 report 中标注（修审查 P0-S1）。

## 4. 关键接口与数据格式

### 4.1 BoardSource（数据源抽象）

```python
class BoardSource(Protocol):
    def start(self) -> None: ...                 # 启板 + 开始推流
    def stop(self) -> None: ...                  # 停流（幂等）
    def health(self) -> StreamHealth: ...        # 最后样本 t_lsl、瞬时/累计采样数
    def meta(self) -> BoardMeta: ...             # board 名、采样率、通道标签、固件
# 实现：CytonSource(serial_port) / SyntheticSource() / Bci2aReplaySource(mat_dir)
```

依据：《换机文档》§5 真机/仿真共享工具链；现状 `Bci2aReplaySource.start` 未初始化 csv_writer 直接崩（审查 S1），统一接口后由基类兜底生命周期。

### 4.2 事件字典（marker_spec 升级 v0.3）

v0.2 全部保留，**新增**（v3 实测已在用但未登记——字典与现实的偏差必须收口）：

| event | 何时 | 附加字段 |
|-------|------|----------|
| `prep_start` | cue 前准备段 | trial_id, label |
| `iti_start` | MI 后 ITI | trial_id, label |
| `judge` | 每个在线判定窗 | trial_id, t_rel, pred, gated_pred, p_max, p_three[], win_start_rel, win_end_rel |
| `v3_baseline_end` / `v3_block_begin` / `v3_block_end` | v3 块结构 | block, cond |
| `v3_self_check_ok` | 开场自检 | — |
| `eeg_stall` / `eeg_resume` | **新增**：断流告警/恢复 | last_sample_t, gap_s（§5.2） |
| `session_integrity` | **新增**：收尾完整性核对结果 | manifest_ok, rows_eeg, span_eeg_s, span_events_s |

行格式沿用 v0.2（`t_lsl/event/trial_id/label/phase/...`）；`label∈{0,1,2}` 冻结；`phase` 枚举扩 `probe/v3`。

### 4.3 Marker 生成接口（唯一出口）

```python

def push_event(events: EventLogger, markers: MarkerPublisher, name, t_lsl, **fields)
```

## 5. 异常处理与容错机制

### 5.1 分级响应模型

| 级别 | 触发 | 动作 | 事件 |
|------|------|------|------|
| L1 提示 | 单导联坏、帧率低、磁盘 <5GB | UI 黄条；采集继续 | client_stats/quality |
| L2 降级 | EEG 断流 2-5s、WS 断开重连中、推理超时 | 暂停状态机推进；推理输出标 `stale=true`；UI 红条 | `eeg_stall` |
| L3 中止 | 断流 >5s、板卡 error、磁盘写失败、abort 键 | 安全停会话：补写 session_end/integrity/manifest 后退出 | `session_integrity(manifest_ok=false)` |

**核心原则：任何异常路径都必须走"会话收尾"**——现状 ws07 无 session_end、无 manifest、eeg.meta 缺失（fnz 实证），正是缺少收尾协议。收尾用 try/finally + `__exit__` 双保险。

### 5.2 数据看门狗（针对 fnz 断流）

- EEGBus 内建：`gap = local_clock() - last_sample_t`；>2s 触发 L2（暂停 trial 推进 + 广播 `health` + 写 `eeg_stall`），>5s 触发 L3。
- **推理陈旧保护**：`judge` 事件增加 `buf_age_s` 字段；窗口数据年龄 >1s 时推理输出强制 `stale=true`，前端/操作台显示灰色，score 统计排除 stale 试次——直接杜绝"恒定 p_three 被误当模型塌缩"（fnz 诊断 §3.4）。
- 恢复：流回来后写 `eeg_resume`，操作台一键"继续/作废本试次"。

### 5.3 会话完整性协议

会话结束（正常或异常）统一执行：

```text
1. 写 session_end（若状态机未能）
2. 校验：events t_lsl ∈ [eeg 首末样本]；EEG span ≥ 0.9×events span；行数=manifest 预期
3. 写 manifest.json（文件清单+行数+sha1）+ session_integrity 事件
4. Summary 页显示 manifest_ok；false 时红字提示"本场数据勿用于 FT"
```

依据：本方案把 fnz 诊断中"人工发现断流"的流程自动化；verify 规则沿用 `verify_phase1_alignment` 判据（span 对齐、t_lsl 单调）。

### 5.4 Preflight（启动预检，替代人工故障速查）

《换机文档》§4-P0-3 的 check_deps 增强 + §6 故障速查表程序化：

```text
[环境] torch/cuda 可用性、brainflow/pylsl/websockets 导入
[大文件] DEFAULT_THREE/TASK ckpt 存在；replay _t0 或全量 out 存在；缺失→打印"请拷贝 <相对路径>"（P0-3 要求的中文提示）
[机位] machine.json schema 校验；bat 无硬编码用户名（检查 %USERPROFILE% 用法）
[状态] operator_defaults.json 存在绝对路径→警告并建议删除（P0-1/2）
[硬件] COM 枚举；BrainFlow 假连接测试（synthetic 快速自检）
[资源] 磁盘剩余（replay 需数 GB）；端口 8080/8765 占用检测（只报不杀——修审查 S4 误杀风险）
```

任何一项失败→交互式向导指路（对应《换机文档》§4-P2-9 首启向导），**不再让 FT 中途 RuntimeError**。

### 5.5 前端容错（冻结文件内的小行为修补）

- `sendContinue` 失败清 `dismissedPromptId` 再重显（修审查 B10 被试卡死）。
- 离线判定改状态码而非文案正则（修 B11 误报）。
- `acquire` 段 `anim=none` 前端强制校验 + console.error + 上报（修 B13）。
- RAF 循环 try/catch，连续 3 帧异常停渲染并上报（修 W-#10）。
- 以上均为《换机文档》允许的"小改一点"范畴（§3.3），不动范式时序。

### 5.6 进程与资源

- 所有长命对象（EventLogger/MarkerPublisher/RingBuffer/EEGBus/BoardSource/StaticServer）`__enter__/__exit__`；orchestrator 装配处一律 `with`。
- 子进程/浏览器启动记录 PID，退出时清理；端口冲突只检测不 `Stop-Process`（修审查 S4）。

## 8. 关键决策依据汇总

| 决策 | 依据 |
|------|------|
| 7 层而非 6 层（domain/session 分开） | 依赖扫描：session_v2/v3/v4 平行复制 40%+，基类需独立层归属 |
