# v3 零样本探针会话设计（引导效果验证 + 新用户模型质量体检）

日期：2026-08-24 · 状态：设计稿（未实现，供工程师按 §6 清单施工）
定位：**第三个会话模式 `v3_session`**，与 v1 Phase2、v2 会话并列。
一句话：用**冻结的零样本底座模型**当"尺子"，在**有引导 / 无引导**两种条件下测量新用户的 MI 质量，同时给操作台提供**实时脑电监视**和**每试次特征卡（ERD / ERS / 偏侧化）**。

---

## 0. 为什么必须单独开会话，而不是在 v2 里加开关

v2 的核心动作是**轮间增量微调**（`session_v2.py:561` IncrementalFinetuner + `:604` ctrl.run_calibration_round）。一旦开跑，模型权重每个轮次都在变——第 2 轮以后的所有判定已经**不是零样本**。"引导是否有效"和"底座对新用户质量如何"这两个问题都要求**全程权重冻结**，否则测量被 FT 污染、无法归因。因此 v3 不是 v2 的配置变体，而是独立会话模式：

| | v2 会话 | v3 探针会话 |
|---|---|---|
| 模型权重 | 轮间增量 FT，持续变化 | **全程冻结**（只读推理） |
| 回答的问题 | 这个人校准后能不能玩游戏 | ① 底座对这个人的零样本质量 ② 动作引导有没有效 |
| 判定结果 | 驱动计分、门控、训练 | **只记录**，不训练、不门控游戏 |
| 引导 | 阶段0 + 轮间各一次 | 作为**被操纵的自变量**（A/B 块） |
| 操作台 | 进度/准入监控 | **实时脑电图 + 每试次特征卡** |

降级策略差异（重要）：v2 无模型时降级为"流程演练"（`session_v2.py:199-201`）；**v3 无模型 = 会话无意义，直接拒跑**并打印自检指引（见接入方案文档自检三件套），不做演练模式。

## 1. 实验设计：验证"动作引导是否有效"

### 1.1 假设与自变量

- **H（主假设）**：操作者动觉引导（两手分别抓握杯子→被试记住抓握动作→睁眼想象复现）能提升 MI 质量，表现为：① 零样本判定准确率上升；② 对侧 mu/beta ERD 加深；③ 偏侧化（laterality）增强。
- **自变量**：块条件，两水平——`no_guide`（无引导直接做试次）与 `guided`（先做一轮动觉引导再做试次）。
- **设计**：被试内 A/B，**块顺序在被试间平衡**（入组时按分配种子定序，写入 meta）：一半人 `no_guide → guided`，另一半 `guided → no_guide`。顺序本身（练习效应/疲劳效应）作为协变量在分析中检查。

### 1.2 因变量（每块都测，块间对比）

| 指标 | 定义 | 口径来源 |
|---|---|---|
| **零样本准确率** | Three 头 argmax vs cue 标签，主判定点 `t_rel=4.0s`（全栅格同时记录） | 与 v2 小考同口径（`session_v2.py:604` predict_window + serial_gating，但**不做门控取舍**，报告原始 argmax 与 gated 两个版本） |
| **置信裕度** | p_three 正确类概率 − 最大竞争类概率 的均值 | 新增 |
| **对侧 mu ERD%** | 100×(P_MI − P_rest)/P_rest，mu=8–13Hz，左手取 C4/CP4、右手取 C3/CP3 | `analyze_mi_features_25.py:94,110,145-154` 原样搬用 |
| **偏侧化 pp** | ERD_同侧 − ERD_对侧（正值越大越好） | 同上，合格线 ≥8pp（`STANDARDS["laterality_pp_ok"]`） |
| **beta ERS/ERD** | βL 13–20Hz / βH 20–30Hz 对侧 ERD% | 同上（ERS=正值即功率上升，照实报告） |
| **静息 mu 占比** | rest 段 mu/(mu+βL+βH) | 同上，合格线 ≥0.40（信号质量哨兵） |

### 1.3 会话结构（约 22–25 分钟）

```
阶段0  自检            模型+LSL 硬校验；失败→拒跑并打印自检指引
阶段1  静息基线 60s    注视+，不判定；测绝对 mu 功率与信号质量（rest_mu_frac）
阶段2  块1（18 trial）  按种子定的顺序：no_guide 或 guided
        [若块1=guided] 先动觉引导（同 v2 阶段0 的等待-确认交互）
阶段3  块间休息 60–120s  坐定、不引导（若下一块=guided 则休息后先引导）
阶段4  块2（18 trial）  另一条件
阶段5  报告            当场出 v3 报告（§5），落盘
```

- 每块 18 trial = 2 子块 × (3L+3R+3Rest 置换)，复用 `build_calibration_schedule` 的置换逻辑（`trial_v2.py`），保证 L/R/Rest 均衡；Rest 试次同时充当块内 ERD 基线。
- 试次时序**与 v2 完全一致**（prep2/cue2/mi6/iti3，`config/v2_session.yaml:37-40`），判定栅格同为 D8 0.6s——这样 v3 指标与 v2 小考指标可直接对齐比较。
- 引导等待复用 `bridge.wait_client_event("v2_guidance_confirm")` 同款交互（`session_v2.py:526`），操作台按钮不变。
- **无准入、无熔断降级、无游戏、无任何 FT**；连续无效只记录不中止（探针会话要完整数据）。

## 2. 后端实时脑电图（操作台）

### 2.1 数据源与链路

v3 会话本就持有 `RingBuffer`（60s 容量、250Hz、8ch，`inference_v2.py:25`），**不新增采集链路**。新增一个发布器线程：

```
RingBuffer ──每 300ms──> 取尾部 2.5s 原始段 (2000×8)
            ──4:1 抽取至 62.5Hz 显示率（或 2:1→125Hz）──> ws 广播
```

- 消息：`{"type":"eeg_frame","t":<lsl_clock>,"fs_disp":62.5,"ch":["Cz","C3","C4","CP3","FC4","FC3","CP4","CPz"],"data":[[...8×N...]]}`
- 注意缓冲区存的是**设备级滤波后**信号（0.5–45Hz + 49–51 陷波，`acquisition/service.py:94-101`），显示足够；特征分析另走 8–30Hz 重滤（§3）。
- 带宽：8ch×375 点×~8 字符 ≈ 25KB/帧 × 3.3Hz ≈ 80KB/s，局域网无压力；**远程监控（方案B）下同样可用**。
- 会话阶段0自检通过后才开播；会话结束/中止时停播（与 `buf.close()` 同生命周期，`session_v2.py:743`）。

## 3. 每试次特征卡（trial 结束后 ≤1s 出）

### 3.1 算法（全部移植自 `analyze_mi_features_25.py`，保证离线/在线同一套标准）

关键口径，三处与离线特征分析**必须一致**，否则卡片数字与离线报告对不上：

1. **不做窗内 z-score**（ERD% 是相对功率变化，z-score 会把尺度抹平）。在线预处理要开一条 `zscore=False` 通路：`OnlinePreprocessor.process` 目前末尾强制 `trial_zscore`（`inference_v2.py:117`），需加参数或新函数，只保留 `car_reference → notch_and_bandpass(8–30)`。
2. **功率用 rFFT 频带均值**：`_bandpowers_fft`（`analyze_mi_features_25.py:94`）原样搬用。
3. **段定义**：MI 段 = cue 后 0–4s（基线校正取 cue 前 0.5s）；Rest 基线 = 本块内 Rest 试次的对应段。与离线 `_side_metrics` 的 rest 窗基线一致。

每试次输出：

```
trial_id · label · 条件块
pred（argmax + gated 两版本）· p_three=[..] · margin
mu_ERD%:  C3 .. C4 .. CP3 .. CP4 ..（对侧加粗）
βL/βH 对侧 ERD%（正值=ERS）
laterality_pp · rest_mu_frac（用块内已积累 Rest 窗，逐试次滚动更新）
评级：按 score_side 的 5 项核心检查打勾（`analyze_mi_features_25.py:220`）
```

- 试次判定窗同时**只记录不训练**：`judgment_fn` 返回 `infer.judge(...)` 后仅把 `p_three/p_task/window` 存进会话存储，**不接 IncrementalFinetuner、不建 replay 池**（即 `session_v2.py:541-576` 整块不搬）。
- 有效试次判定沿用 D8 计分（`timing.scoring_config()`），保证与 v2 小考可比；但**不触发熔断**（`session_v2.py:284-286` 的 abort 逻辑在 v3 改为只记录 `invalid_streak_max`）。

### 3.2 操作台卡片消息

- 消息：`{"type":"trial_features", "trial_id":…, "label":…, "block":…, "cond":"guided", "features":{…}, "grade":{…}}`，trial_end 后由后端计算并广播；操作台追加到特征卡列表（最多显示最近 6 张，全量在 JSONL）。
- 卡片视觉：三列（判定 / ERD 热表 / 检查打勾）；对侧通道高亮；ERD≤−15% 绿色、偏侧≥8pp 绿色，否则灰/红。

### 3.3 落盘

会话目录下新增：
- `v3_trial_features.jsonl`（每行一试用，含特征 + 判定 + 块条件）
- `v3_segments/`（每试次连续段 `.npy`：cue−2s 至 mi_end，原始设备滤波信号 (T,8)，约 200KB/试次 × 36 ≈ 7MB/会话；供离线复核与重算）
- `v3_report.json` + `v3_report.md`（§5）

## 5. 零样本质量报告（阶段5 当场出）

`v3_report.json/md` 内容：

1. **分块准确率表**：`no_guide` vs `guided`，主判定点 4.0s 的 argmax acc + gated acc + 混淆矩阵（3×3）+ 裕度；
2. **分块特征表**：对侧 mu/βL/βH ERD%、偏侧 pp、rest_mu_frac、时间形态（time_drop/trough，`analyze_mi_features_25.py:160-181` 同款）；
3. **引导效应**：Δ(guided − no_guide) 各指标 + 方向结论（本被试层面只做描述，显著性检验留给 T12 跨被试分析）；
4. **底座质量定级**（对新用户零样本质量的回答）：
   - acc ≥0.60 → 零样本即可用（罕见，记录之）；
   - 0.45–0.60 → 需常规标定（走 v2 预期路径）；
   - <0.45 且特征评级"弱/不明显" → 标记 `weak_mi_candidate`，提示操作者重点引导；
   - 参照锚点：Stieger 域零样本 k=0 = 0.410（爬坡曲线起点），自采新用户低于 0.35 即提示检查电极/引导。
5. 操作台 Summary 页（`view-summary`）显示报告摘要 + 「打开会话文件夹」。

## 7. 数据治理与 15/5 计划的衔接

- meta 打 `phase_mode="v3_session"`；**v3 数据默认不进入底座 v2 训练池与回放池**（评估性质、且无引导条件块会引入分布差异）。若日后想用，走显式审批并在数据登记表注明。
- Phase4 切窗：v3 试次结构与 v2 标定同口径，`phase4_v2` 管道**可以**切 v3 数据（用于离线复核），但产出物同样打 `v3` 标签隔离。
- 在 15+5 任务书中的位置：v3 是 **A3（引导剂量-效应）** 的测量工具，可安排在微调组首访（v2 之前跑一次，约 25 分钟）作为基线；留出组若跑 v3，其数据同样遵守三不进入。
- 换底座模型后（接入方案 §3 换模型流程），v3 是对新用户做"新底座体检"的第一站——比 v2 全会话便宜，先测零样本再决定标定策略。

| V3 | 零样本冻结证明 | 会话前后对同一窗推理，p_three 完全一致（位级）；报告 `frozen=True` |
| V4 | 脑电图性能 | `eeg_frame` 周期抖动 <±50ms；操作台渲染帧率不掉（特征计算 <500ms/试次，不阻塞试次状态机——特征计算放试次间 ITI 内完成） |
| V5 | 顺序平衡 | 连跑 4 个假被试（种子不同），meta 中 `v3_block_order` 两种顺序各半 |
| V6 | 拒跑逻辑 | 删 ckpt / 关采集各测一次：阶段0 明确报错拒跑，错误文案含自检三件套（走 bat、开采集、ckpt 路径） |

## 9. 边界与非目标

- **不做**在线 100ms 滑窗判定（接入方案扩展B，v3 同样不做）；
- **不做**引导剂量的多级梯度（只有 有/无 两水平；多级留给任务书 F5 爬坡曲线的离线分析）；
- **不做**神经反馈式实时 ERD 显示给被试（被试屏保持纯净；特征卡只在操作台）；
- v3 不产生任何可部署权重；它只产出**数据 + 报告**。
