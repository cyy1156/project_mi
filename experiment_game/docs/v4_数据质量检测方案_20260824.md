# v4 数据质量检测方案

> 日期：2026-08-24（v2 设计：结合 v3 真机复盘）  
> 状态：方案定稿，待实现

---

## 0. 背景：为什么需要 v4（v3 复盘结论）

2026-08-24 共 **67 场** `opsmoke` v3 烟雾测试，仅 **6 场**写出特征文件；完整场次 **左右模型准确率 0%**。根因不是算法，而是 **帽检时机与粒度不足**：

| 病灶 | 典型会话 | 现象 | v3 现有门禁为何漏过 |
|------|----------|------|---------------------|
| **共模漂移** | `…200329` | 整段 cm_ratio≈**69**，\|x\|max≈1132 µV | 帽检仅在 60s 基线末 **一次性**汇总；判定点逐窗 QC 未拦 |
| **单通道暴胀** | `…223139` | CP4 std≈103 µV，整段中位 std≈40（<60 上限） | 中位 std 掩盖单通道异常；无逐通道热力图 |
| **死通道** | `…200329` | C3 CAR 后 std≈9 µV（原始看似有数） | `dead_channel` 只在判定点触发，操作员看不到趋势 |
| **大幅伪迹** | `…230231` | 升级 QC 后 4/4 MI 全 `signal_bad` | 说明阈值方向对，但发生在 **v3 已跑起来之后** |

v3 帽检（`summarize_baseline_hat_check`）的问题：

1. **一次性**：操作员在 60s 内动了一下，末段恰好干净 → 误 PASS。  
2. **无连续稳定性**：没有「连续 15s 达标」门槛。  
3. **无交互修帽回路**：FAIL 后只能整局重开，不能「边修边看」。  
4. **与实验耦合**：必须先加载 S3 权重、走 v3 流程，成本高。

**v4 定位**：实验前 **独立、无模型、连续、可交互** 的数据质量诊断；PASS 后再开 v3。

## 1. 目标与边界

### 1.1 目标

新增 **`v4_session`** 会话模式：

- 戴帽接好后，操作员静坐 **30–120s**（默认 90s）
- 每 **3s** 滚动评估信号质量（复用 `signal_quality.py`）
- **连续 5 窗（15s）全 ok** → 显示 PASS，提示可开始 v3
- 实时展示 **8 通道热力图 + 指标卡 + 中文操作建议**
- 会话结束输出 **`v4_report.json`**，可对比历史

### 1.2 非目标（v4 不做）

- 不跑 MI trial、不 cue、不判 Left/Right
- 不加载 `s3_task_ckpt` / `s3_three_ckpt`
- 不替代 Cyton **L1/L2 串口预检**（`preflight_probe` 仍保留）
- 不保证「一定能做出 MI」——只保证 **幅值/共模/通道健康** 在可解码区间

### 1.3 推荐工作流

```
Cyton 预检 (COM + v 命令)
    → v4_session（修帽直到 PASS）
        → v3_session / v2_session（正式实验）
```

## 3. 信号质量核心：`diagnose_eeg_window()`（新增）

在 `signal_quality.py` 扩展，**不改动** `assess_eeg_window()` 现有语义（v2/v3 判定点仍用它）。

### 3.1 窗级判定（与 v3 一致）

先调 `assess_eeg_window(win, cfg)` → `window_ok`、`reason`、`metrics`。

### 3.2 逐通道诊断（v4 专用）

对每个通道 `i`（顺序 = `CHANNEL_ORDER`）独立计算：

| 检查项 | 条件 | 通道 reason |
|--------|------|-------------|
| `flatline` | 该通道 \|x\| 几乎为 0 的采样占比过高 | `flatline` |
| `low_std` | `ch_std[i] < min_per_channel_std_uv` | `low_std` |
| `high_std` | `ch_std[i] > max_per_channel_std_uv`（默认 60） | `high_std` |
| `saturation` | `max(|x_i|) > max_peak_uv` | `saturation` |
| `dead_car` | `car_std[i] < min_car_std_uv` | `dead_channel` |
| `imbalance` | `ch_std[i] / median(ch_std) > max_channel_std_ratio` | `imbalance` |

通道 `ok` = 以上均无。`per_channel_ok[i]` 与 `per_channel_reason[i]` 一并返回。

> **复盘依据**：`200329` 的 C3 应标红 `dead_car`；`223139` 的 CP4 应标红 `high_std` / `imbalance`，即使中位 std 仍 < 60。

### 3.3 问题列表与操作建议

`problems: List[{channel, reason, detail, hint}]`，`hint` 由规则表生成：

| reason 模式 | 中文 hint |
|-------------|-----------|
| `common_mode`（窗级） | 参考电极接触不良：检查 **SRB2 + Bias**，轻压耳后/乳突 |
| `dead_channel` ×1 | `{Ch} 去共模后无信号：补胶/按紧该电极` |
| `dead_channel` ×≥3 | 多通道死通道：先查参考电极，再逐个按通道 |
| `artifact` / `high_std` | 大幅伪迹：减少头动/咬牙，检查导线拉扯 |
| `saturation` | 饱和：检查增益/电极是否翘起造成跳变 |
| `low_std` / `flatline` | 信号过平：电极可能未接触皮肤 |
| `channel_imbalance` | 通道间幅度悬殊：检查松动电极或导电膏不均 |

窗级 `rolling_verdict`：

- `pass`：`window_ok` 且 streak 已达 `pass_streak_required`
- `warn`：`window_ok` 但 streak 未满
- `fail`：`not window_ok`

## 4. 配置：`V4Config`

`experiment/v4_config.py`，模式同 `V3Config`：

```python
@dataclass
class V4Config:
    # 会话
    duration_s: float = 90.0           # 最长检测（可手动提前结束）
    eval_interval_s: float = 3.0         # 推送间隔 = 评估窗长
    eval_window_s: float = 3.0
    pass_streak_required: int = 5        # 连续达标窗数（5×3s=15s）
    auto_stop_on_pass: bool = False    # PASS 后是否自动结束

    # 采集 / 显示
    eeg_frame_interval_s: float = 0.25 # 可选：轻量波形（降采样）
    save_eeg_csv: bool = True          # 录制便于回放校准
  channel_labels: tuple = CHANNEL_ORDER  # 冻结，与 inference_v2 一致

    # 信号阈值 → SignalQualityConfig（与 v3 默认对齐）
    signal_quality_enabled: bool = True
    signal_min_median_std_uv: float = 3.0
    signal_max_median_std_uv: float = 60.0
    signal_min_peak_to_peak_uv: float = 8.0
    signal_max_ptp_uv: float = 400.0
    signal_max_peak_uv: float = 1000.0
    signal_min_per_channel_std_uv: float = 2.0
    signal_max_per_channel_std_uv: float = 60.0   # v4 新增：单通道上限
    signal_min_active_channels: int = 6         # v4 收紧：至少 6/8（v3 为 3）
    signal_max_channel_std_ratio: float = 20.0
    signal_min_car_std_uv: float = 2.0
    signal_max_common_mode_ratio: float = 0.85

    fs: int = 250
```

**相对 v3 的默认收紧**（可 yaml 覆盖）：

- `min_active_channels`: 3 → **6**（避免「只有 3 路有数」仍过线）
- 新增 `max_per_channel_std_uv`（单通道暴胀必 FAIL）

`config/v4_session.yaml` 提供上述默认值；Setup 页 **不暴露** 阈值滑条（避免误调），仅高级模式 / yaml 可改。

## 5. 后端会话逻辑：`session_v4.py`

```python
def run_v4_session(events, bridge, buf, cfg: V4Config, *, on_console, paths) -> dict:
```

主循环（在独立线程或同步 `wait_until` 中）：

1. `bridge.broadcast({"type": "v4_start", ...})`
2. `bridge.broadcast` HUD：`"请静坐放松，正在检测信号质量…"`
3. 每 `eval_interval_s`：
   - `win = buf.snapshot_tail(eval_window_s)`
   - `diag = diagnose_eeg_window(win, cfg)`
   - `monitor.update(diag)` → streak / history
   - `bridge.broadcast({"type": "v4_quality", **diag, "pass_streak": monitor.streak})`
   - 若 streak 从 4→5：额外 `v4_pass`
4. 退出条件：`duration_s` 到 / 操作员 abort / `auto_stop_on_pass` 且已 PASS
5. `summary = summarize_v4_session(monitor.history)`
6. 写 `paths.session / v4_report.json`，`events.emit("v4_end", **summary)`
7. `bridge.broadcast({"type": "v4_summary", **summary})`

**依赖**：仅需 LSL + RingBuffer（与 v3 相同采集栈），**不** `diagnose_v3_deps`。

## 9. 与 v3 的关系

| 维度 | v3_session | v4_session |
|------|-----------|-----------|
| 时机 | 实验中（baseline 末一次性帽检） | **实验前**独立跑 |
| 模型 | 必须 | **不需要** |
| 评估 | 60s 汇总 + 判定点逐窗 | **全程**每 3s + 连续 15s streak |
| 交互 | 仅提示，不强制停 | 专为 **边修边看** 设计 |
| 通道 UI | 功率条（无逐通道 QC 色） | **热力图 + 原因** |
| 通过后 | 进入 block | 建议转 v3；可一键切模式（沿用 COM/采集） |

v3 侧保留现有 `summarize_baseline_hat_check` 作为 **二次确认**；v4 PASS 后 v3 帽检仍可能 WARN（例如实验中途松动），二者互补。

## 附录 A：干净信号参考值（与 v3 QC 计划一致）

| 指标 | 正常（Cyton 滤波后） | 坏数据典型 |
|------|---------------------|-----------|
| 每通道 std | **5–120 µV**（窗中位；OpenBMI 采集滤波 P5–P95 约 7–61） | &lt;5 空帽/合成；&gt;120 大幅伪迹 |
| 峰峰值 | **40–800 µV** | 过低无动态；过高伪迹 |
| CAR 后 min std | **≥ 1.2 µV** | 死通道 / 近纯共模 |
| 共模比 | **≤ 1.25** | 原始头皮中位≈0.93；旧 0.85 会误杀 OpenBMI |
| 幅度峰值 | **&lt; 800 µV** | 饱和/跳变 |
| 有效通道 | **≥ 6 / 8**（单通道 std ≥ 3） | 多电极接触不良 |
| 通道间 | 各动各的（CAR 后有差分） | 8 通道几乎同一波形 |

## 附录 B：v3 左右判错与 v4 的关系

v3 模型 0% 准确率的链条是：**伪迹 EEG → Task 头全 Rest → ERD 反向 → 左手偏侧假阳性**。  
v4 **不能**直接预测「左右能判对」，但能阻断 **cm_ratio 过高 / 死通道 / 单通道暴胀** 三类在复盘中最常见的根因，避免在坏信号上浪费 30+ 分钟 v3 流程。
