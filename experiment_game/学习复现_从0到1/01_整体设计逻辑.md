## 1. 系统在干什么

`experiment_game` 是一条 **运动想象脑电实验流水线**：

1. 被试戴 Cyton 8 导帽，看网页游戏（想象左/右手抓杯子，或静息）  
2. 电脑同时：**采脑电**、**打时间标签**、**在线分类**、**计分反馈**、**落盘**  
3. 一场结束后，可用 **Leave-Next** 对被试模型做少样本微调  

**核心矛盾**：游戏画面可以卡；**「哪一毫秒开始想象」的标签不能漂**——模型靠「标签时刻 + 那段 EEG」学习。

现行范式（OpenBMI-Align v1）一个试次：

```text
Rest 4s → prep 2s → Cue(=MI起点) → MI 4s → ITI 3s
```

详见冻结表 F1/F2/F25/F26。

## 2. 目录分层（按「谁依赖谁」理解）

| 层 | 目录 | 干什么 | 对应代码入口 |
|----|------|--------|----------------|
| 配置 | `config/` | 范式、会话、E1f 权重路径 | `protocol.yaml` · `v3_session.yaml` · `e1f_four_member.json` |
| L1 核心 | `core/` | 通道序、路径、原子写、切窗几何 | `core/channel_layout.py` · `core/windowing.py` |
| L2 运行时 | `runtime/` | EEGBus、CSV 录制、健康 | `runtime/eeg_bus.py` · `csv_recorder.py` |
| L2 流水线 | `pipeline/` | **离线**微调（不碰实时流） | `pipeline/finetune.py` |
| L2 采集门面 | `acquisition/` | 封装 BrainFlow→LSL（串口在这） | `acquisition/service.py` |
| L3–L5 实验 | `experiment/` | 状态机、推理、计分、编排、WS | `orchestrator.py` · `session_v3.py` · `trial_v2.py` · `inference_v2.py` · `trial_scoring.py` |
| 离线后处理 | `offline/` | 会话后切窗 / Phase4 | `offline/` |
| 入口 | `tools/` + `*.bat` | 启动操作台 | `tools/open_operator.py` |
| 前端 | `web/` | 操作台 + 被试诱导页 | `web/operator.html` · `web/index.html` |
| 数据 | `data/` | sessions / subjects / models | 运行后生成 |

底层板卡驱动实际在仓库：`collect_data/LSL_connect_model/...`（由 `AcquisitionFacade` 导入）。

## 3. 两条流（记住这个就抓住骨架）

### 3.1 数据流（宽：脑电样本）

```text
COM 串口 (Cyton)
  → BrainFlow (lsl_connect ServiceManager)
  → LSL 流 "OpenBCI_EEG" @250Hz
  → RingBuffer.attach_lsl()          # experiment/inference_v2.py
  → EEGBus.publish                   # runtime/eeg_bus.py
       ├─ CsvRecorder → eeg.csv      # runtime/csv_recorder.py · live_capture.py
       ├─ InferenceService           # 在线取窗+模型
       ├─ 前端波形 (WS)
       └─ 健康监控
```

你熟悉的串口：**只出现在最上游**。进 LSL 之后，后面代码几乎不再碰 COM。

### 3.2 控制流（窄：事件与指令）

```text
试次状态机 TrialStateMachineV2       # experiment/trial_v2.py
  → MarkerPublisher → LSL Markers    # experiment/markers.py
  → EventLogger → events.jsonl
  → WsBridge → 浏览器 UI             # orchestrator + web/js
  → 判定时刻触发 InferenceService.judge
  → MiTrialTracker 累计 → 试次得分   # trial_scoring.py
```

**数据流**管「电压」；**控制流**管「现在是 Rest 还是 MI、该不该判分」。

## 4. 一次 v3 探针会话的生命周期

```text
open_operator.bat
  → tools/open_operator.py
  → OperatorService (experiment/orchestrator.py)
       HTTP :8080 提供 web/
       WS   :8765 收发 JSON

Setup 页：登录被试 → 开采集(COM/合成) → 选 v3 → E1f → 开始
  → create_session_dir                 # experiment/session.py
  → AcquisitionFacade.start            # acquisition/service.py
  → LiveEegCapture.start               # experiment/live_capture.py
  → session_v3 跑 blocks×trials        # experiment/session_v3.py
       每个 trial：trial_v2 时序
       窗尾到达 → OnlinePreprocessor → E1f 融合 → F5 计分
  → 会话结束写 alignment / manifest
  →（可选）Summary 里 Leave-Next 微调  # pipeline/finetune.py
```

落盘典型结构：

```text
data/sessions/<subject>_<session>_<stamp>/
  eeg.csv · events.jsonl · run_config.json · session.meta.json
  continuous/ · by_phase/ · alignment/ · manifest.json
```

被试资产：

```text
data/subjects/<id>/
  sessions/ · models/current · models/ft_runs/
```

## 5. 配置三分法（别把「菜单」和「炒菜」混了）

| 层 | 文件 | 含义 |
|----|------|------|
| 范式 | `config/protocol.yaml` | 永远该长什么样：通道、窗、时序、读出 |
| 会话默认 | `config/v3_session.yaml` | v3 探针默认块数、E1f 路径等 |
| 本场快照 | 会话目录 `run_config.json` | 这一场实际用了什么（可复现） |
| 机位 | `machines/<name>/machine.json` | 这台电脑的 COM、环境 |

改协议：先改配置 + 测试，再改文档（冻结 F24）。

## 6. 在线判定 vs 采后微调（别混）

| | 在线（会话中） | 采后（会话后） |
|--|----------------|----------------|
| 目的 | 实时反馈 / 计分 | 个性化权重 |
| 主代码 | `inference_v2` · `trial_scoring` · `adapt_engine/e1f` | `pipeline/finetune.py` · Leave-Next 工具 |
| 读出 | F5：因果平滑 + 多数票 | 同 F5 评估 hold 集 |
| 默认底座 | E1f 四成员 three 融合 | 通常 FT shallow 的 task+three |
