# 00 · 写代码小白指南（必读）

> 能力不强没关系。本学习路径的方法是：**对照原版「一个函数一个函数」仿写**，不是从头发明架构。

## 1. 你每天只做这一件事

```text
① 打开本模块笔记里的「原版精读表」
② 在 Cursor 里打开那个 .py，只跳到指定函数（用 Ctrl+F 搜函数名）
③ 用纸抄下：函数名、参数、返回值、三步在干什么
④ 在 mi_scratch 里先写空函数 + 测试（测试会红）
⑤ 自己填实现，直到测试变绿
⑥ 再打开原版函数，问：行为一样吗？差在哪写进 README
```

## 2. 「参考」到底怎么参考（很重要）

| 可以做 | 不可以做 |
|--------|----------|
| 看原版函数的**参数和返回值**，照着设计你的 API | 整文件复制粘贴改个名交差 |
| 看原版 **if/for 的步骤顺序**，用自己的话重写 | 看不懂就让 AI 生成一大坨再不读 |
| 把原版里的**数字**抄到 yaml（3.0、0.1、250） | 把 `orchestrator.py` 上千行搬进作业 |
| 某一两个公式（融合、平滑）对着公式实现 | 跳过测试「感觉写对了」 |

**允许 AI 帮你**：把你的空函数签名 + 测试贴给 AI，说「按测试实现，不要抄原版文件」。  
**你必须自己**：能指着每一行说出它干什么；测试必须是你理解过的。

## 3. 在 Cursor 里怎么读大文件（不会迷路）

1. 打开文件后 **Ctrl+F** 搜笔记里的函数名，例如 `causal_smooth_pred_sequence`。  
2. 只读这一个函数（大约几十行），读完关掉或折叠。  
3. 不要从上到下滚读 `orchestrator.py` / `inference_v2.py` 全文。  
4. 类很大时，只读笔记点名的方法，例如 `RingBuffer.push`、`RingBuffer.window_ending_at`。

## 4. 测试怎么写（最小模板）

```python
# tests/test_xxx.py
from mi_scratch.xxx import your_func

def test_something():
    out = your_func(...)
    assert out == expected  # 或 assert abs(a-b) < 1e-6
```

先写 `assert False, "还没实现"` 也行，再改成真断言。  
在 `mi_scratch` 目录跑：

```text
python -m pytest tests/test_xxx.py -q
```

## 5. 卡死了怎么办（按顺序）

1. 把测试期望写清楚（输入是什么、输出应该是什么）。  
2. 只打开原版**一个**对照函数，看它返回什么。  
3. 在本模块笔记「常见坑」里找。  
4. 仍然不会：带着「我的测试代码 + 原版函数名」来问老师/AI，不要丢整个仓库。
