第一人称运动想象脑机接口实验系统：Three.js 浏览器诱导 + Python 控制器跑状态机（fixation→cue→mi→hold→rest→transition）+ BrainFlow/LSL 采 EEG + 打标落盘 + 切窗到训练。**时序对齐与"正式采集段绝对静止"是数据有效性的两条红线。**

## 4. offline/ + acquisition/ + machines/ + tests/ 模块问题

### 严重

- **S1（A1）** 通道顺序不一致 — `offline/channels.py:19-37` `TARGET_CHANNELS=[C3,C4,Cz,CP3,CP4,CPz,FC3,FC4]`（**设备序**）；`offline/openbmi_align_cut.py:21` `FROZEN=[Cz,C3,C4,CP3,FC4,FC3,CP4,CPz]`（**模型序**，与 `experiment/channel_layout.py:25-34` `MODEL_INPUT_CHANNEL_ORDER` 一致）。`pipeline.py` 走设备序，`phase4_v2`/`openbmi_align_cut` 走模型序。两管道 `to_model_tensor`/`np.stack(...,None,...)` 只加通道维不 permute → 产出张量通道排列不同。`pipeline.py:57-72` sanity_check 只校验形状不校验通道。**必须先定夺唯一规范通道序。**
- **S2（A2）** 窗长不兼容 — `offline/epochs.py:23-25` `WIN_SEC=2.0, FS_OUT=250, N_TIMES=500`；`pipeline.py:31` 输出 `(N,1,8,500)`；`phase4_v2.py:105,119` 走 cue 后 4s 任务段再切 3s 滑窗=750 点。两管道时间维度不同，且与项目计划"cue 后 0-4s=MI"描述不完全吻合（前者只取 2s）。

## 6. 跨模块系统性问题（需全局整改）

1. **切窗双轨制（最致命）** — offline 有两套互不兼容切窗管道：`pipeline.py`（设备序、2s/500 点、窗内基线）vs `phase4_v2*`/`openbmi_align_cut`（模型序、3s/750 点、cue 前基线）。二者产出张量通道排列+时间长度都不同，一个管道训练的模型无法直接用于另一管道。tools 内还重复实现第三/四套切窗。**必须先定夺唯一规范（通道序、窗长、基线方式、训练阶段白名单），再让所有代码对齐，否则任何跨管道训练/推理静默出错。**
2. **训练集定义不一** — `phase4_v2` 把 learn/adapt 切进标定集，`pipeline`/`phase4_service` 仅 acquire。需明确 learn/adapt 是否入训练。
3. **时序硬编码 4.0s 满天飞** — alignment/session_v3/inference_v2 等多处硬编码 4.0，与可配置 timing 冲突。应统一从 cfg/timing 读。
4. **marker 格式不统一** — 有 `format_payload` 统一函数却大量 f-string 手拼。
5. **非原子写泛滥** — meta.json/registry.md/各种 JSON/torch.save/write_text 普遍直接覆盖，崩溃截断丢数据。应统一 `atomic_write_text`/`atomic_torch_save` 工具。
6. **资源管理缺失上下文管理器** — EventLogger/MarkerPublisher/RingBuffer/AcquisitionFacade 均无 `__enter__/__exit__`，异常路径泄漏文件/LSL outlet/BrainFlow 句柄/串口。
7. **sys.path hack 满天飞** — 大量模块顶部 `sys.path.insert` 指向 `code/preprocess_lab`/`collect_data`，脆弱且遮蔽同名模块。应正式打包 pip install -e。
8. **无 logging 框架** — 全项目 print，无级别/时间戳/文件落盘，实验现场出问题无可查日志。
9. **魔法数字散落** — 采样率 250、窗长 750/3s、hop 0.1、下采样 4、cue 前基线 2.0 等在各模块各定义。应抽 `config/pipeline_constants.py`。
10. **重复代码** — `_ser`/切窗/`pred_distribution`/`_eval_acc`/`trial_majority_acc`/`LABEL_*` 常量/`hand_from_label` 等多处重复。
11. **测试脆弱** — `assert` 做控制流（-O 下失效）、断言私有属性、无依赖守卫、未覆盖关键路径（S1 漏网）。
12. **会话/run 戳硬编码** — tools 多脚本把特定被试会话名、训练 run 戳写死源码，迭代成本高。
