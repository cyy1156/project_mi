## 1. 高severity

### H1. 局域网内任何人可控制实验会话（无鉴权 WS）
- **位置**：`experiment/ws_bridge.py:228-236`（`websockets.serve(..., origins=None)`）；`ws_bridge.py:293-344`（`_handle_operator`）；`experiment/orchestrator.py:121,276`、`tools/open_operator.py:51`（绑定 `0.0.0.0`）
- **原因/影响**：为 LAN 监控把 origins 完全放开且全程无握手鉴权。同一网段任意主机连上 WS 后可直接发送 `abort` / `pause` / `reject` / `gate_ok`，**中断或篡改正在进行的被试采集**（`ws_bridge.py` 直接 `self._client_events[mtype].set()`）。实验数据完整性问题，不是普通安全卫生问题。
- **建议**：加共享 token 握手（首条消息校验，拒绝即断开）；`origins` 收紧为本机 + 已知监控机；`abort` 这类破坏性事件额外要求二次确认字段。

### H2. 前端把服务端字段直接拼进 innerHTML
- **位置**：`web/js/operator.js:275-278`（另 552、688、2223、2861）；`_labelTag`（182-186）不做转义
- **原因/影响**：`viewing.label_name / pred_name / trial_id` 未转义即拼入 `meta.innerHTML`。这些字段的源头含被试名/登记输入，一旦经 WS 回流即可注入脚本，配合 H1 构成 LAN → 浏览器执行链。
- **建议**：统一改用 `textContent` 赋值，或封装 `_esc()` 后再拼接。

### H3. 未提交改动已增至 +1737/−335（38 文件 + 5 个新文件）
- **位置**：git 工作区（含 `core/windowing.py`、`experiment/session_v2/v3.py`、`orchestrator.py`、`web/js/operator.js`、`pipeline/ft_policy.py` 等）；**外溢到仓库其他目录**：`../code/adapt_engine/`（4 文件）、`../requirements.txt`、`资料/模型训练/`（5 个 md）
- **原因/影响**：昨天 P0（905 行）不但没提交反而翻倍。`ft_policy.py`、`e1f_all4_ft.py`、`ft_promote_extras.py` 这批新逻辑完全无版本保护。
- **建议**：今天必须提交，可拆 4 笔：`fix(windowing)+core` / `feat(ft-policy,e1f_all4)` / `feat(operator-ui)` / `docs+资料`。adapt_engine 的 4 个文件单独一笔。

### H4. `ft_policy.json` 解析失败静默回退，而默认策略是「强制晋升」
- **位置**：`pipeline/ft_policy.py:27-28`（`except Exception: pass`）；默认值 `force_promote_on_gate_fail=True`（`ft_policy.py:14`），`config/ft_policy.json` 同样为 true
- **原因/影响**：**新文件**。JSON 写坏（多一个逗号、编码错）时策略静默退回默认，而默认恰是「门控失败也强制晋升模型」。也就是说：**策略文件一旦损坏，最有风险的行为会无声生效**，操作台看不到任何异常。
- **建议**：解析失败至少 `log.warning` 并在返回的 out 里带 `policy_parse_ok=False` 字段，让调用链能看到；更稳妥：解析失败直接抛，fail-fast 优于静默降级。

### H5. `softmax(logits)[:, :n_out]` 静默切片导致系统性低 acc
- **位置**：`tools/run_exp32_leave_next_dual_model_gate.py:164`
- **原因/影响**：**新文件**。若模型输出类别数 ≠ 3，切片不报错而是返回错误形状矩阵，argmax 后与 y3 比对得出**系统性偏低且无告警的准确率**——这会污染 exp32 的门控对比结论。
- **建议**：`assert logits.shape[-1] == n_out` 后再 softmax。

### H6. 5 处数据链路静默吞异常（基线全部未修）
- **位置与影响**：
  - `acquisition/service.py:303-304`：`mgr.stop_acquisition()` 失败被吞 → **下个会话可能重复触发采集**
  - `experiment/inference_v2.py:127-128`：`bus.publish` 失败被吞 → 推理用陈旧数据且无告警（ws07 同型故障）
  - `experiment/live_capture.py:56-57`：退订失败被吞
