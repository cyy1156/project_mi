## 五、遗留风险与建议（按优先级）

### P1 — 建议近期处理

1. **窗张量存在两种约定，易踩坑**
   `slide_windows` 产出 `(T, C)` = (750, 8)，而 `to_nchw` 期望入参为 `(C, T)` = (8, 750)。
   二者混用会静默产出 `(N,1,750,8)` 而非 `(N,1,8,750)`，**形状合法但语义错误**。
   建议：给 `slide_windows` 增加 `transpose` 关键字或在 docstring 顶部加粗警告；长期方案是统一为 `(C,T)`。

2. **训练侧 `D:/MI/code/preprocess_lab` 仍是切窗数学的"另一份真相"**
   现在 core 是 vendor 副本，两边可能再次漂移。建议把 fidelity 校验加入定期检查，
   或在训练侧改为直接引用 `experiment_game.core.windowing`。

3. **fnz 微调效果仍差**（heldout MI 41.7%，门控失败按 F8 强制晋升）
   属数据/域匹配问题，非重构范围，但下一轮采集前需要关注。

### P2 — 可选优化

4. `experiment/channel_layout.py` / `atomic_io.py` 转发薄文件：等归档脚本改造后可直接删除。
5. `orchestrator.py` 仍是大文件（约 2800 行）：依赖注入已解环，dispatch 表拆分可延后。
6. `data/sim_subjects/`（未跟踪）与 `cyy / fnz / fnz_1 / test` 测试目录：清理项，非阻塞。
7. git 工作区现存 3 处未提交项（资料文档 1 处 + `.workbuddy/` + `data/sim_subjects/`），建议一并整理。
