# 远程监控改造清单（方案 B · 局域网监控端）

> 日期：2026-08-24 · 决策：采集战役采用**方案 B**——后端留在实验机（跟着放大器走），操作台在第二台设备上通过局域网打开。  
> 本文是工程改造与验证清单。  
> **代码状态（同日）**：§1.1–1.3 已落地；启动用 `open_operator_lan.bat` 或 `python -m experiment_game.tools.open_operator --host 0.0.0.0`。防火墙（§2）与 V1–V5 实测仍须在实验机完成。  
> 方案对比（A 双屏 / B 局域网 / C 后端搬离）见本次决策记录：C 已否决（Cyton dongle 物理距离约束 + 无性能理由 + 多一跳故障点）。

## 0. 拓扑（改造后）

```
[放大器 Cyton] --2.4GHz--> [USB dongle] --USB--> [实验机/后端]
                                                    ├─ 显示器1（被试）：诱导页/场景页（本机 127.0.0.1 打开，不变）
                                                    └─ HTTP :8080 + WS :8765（绑 LAN 地址）

```

**关键事实（已核对代码）**：前端无需任何改动——
`web/js/operator.js:3` 与 `web/js/main.js:6` 的 WebSocket 地址均用 `location.hostname` 自动推导：监控端从哪个地址打开页面，就自动连哪个地址的 `:8765`。改造只在后端绑定地址与防火墙。

## 1. 代码改动（3 处，均为参数级）

### 1.1 `experiment/orchestrator.py:81-82` —— 服务绑定地址参数化

现状：
```python
self.bridge = WsBridge(port=ws_port)
self.http = StaticServer(self.web_root, port=http_port)
```
两处的 `host` 均取默认值 `"127.0.0.1"`（`ws_bridge.py:20`、`http_static.py:26`）。

改法（推荐）：给 `OperatorService.__init__` 增加 `serve_host: str = "127.0.0.1"` 参数，并传给两个服务：
```python
self.bridge = WsBridge(host=serve_host, port=ws_port)
self.http = StaticServer(self.web_root, host=serve_host, port=http_port)
```
`start()` 里的端口占用检查（L110-115，查 `127.0.0.1`）**保持不变**——本机占用检测仍然有效。

### 1.2 `tools/open_operator.py:33` —— 增加 `--host` 命令行参数

现状：`svc = OperatorService(http_port=args.http_port, ws_port=args.ws_port)`。  
改法：argparse 增加 `--host`（默认 `127.0.0.1`，远程模式传 `0.0.0.0`），透传给 `OperatorService(serve_host=args.host, ...)`。  
`open_operator.bat` 远程模式加参数：`--host 0.0.0.0`。

### 1.3（可选，体验项）`orchestrator.py:99-107` 打印的 URL

`operator_url`/`subject_url` 目前硬编码 `127.0.0.1`。当 `serve_host=0.0.0.0` 时，终端提示里额外打印本机局域网 IP（`socket.gethostbyname(socket.gethostname())` 或遍历接口），方便监控端抄地址。不改也不影响功能。

**不改的**：前端 `operator.js` / `main.js`（自动推导，已验证）；`StaticServer`/`WsBridge` 类本身（保留默认 127.0.0.1，本机模式零变化）。

## 2. 防火墙（实验机，管理员权限执行一次）

```bat
netsh advfirewall firewall add rule name="MI-EEG operator HTTP 8080" dir=in action=allow protocol=TCP localport=8080 profile=private
netsh advfirewall firewall add rule name="MI-EEG operator WS 8765"   dir=in action=allow protocol=TCP localport=8765 profile=private
```

## 3. 网络布置

| 项 | 约定 |
|----|------|
| 连接方式 | **优先有线**；WiFi 时两台设备同一台路由/AP，勿跨网段 |
| 实验机 IP | 固定（路由器静态分配或本机静态 IP），避免每天换地址；`ipconfig` 记录入登记表 |
| 安全 | `0.0.0.0` 监听所有网卡——仅在可信私有网络使用；若环境复杂，改绑具体局域网 IP 而非 0.0.0.0 |
| 被试屏幕 | 不变：接在实验机上，诱导页本机打开（127.0.0.1 仍可用） |

## 4. 使用流程（采集日）

1. 实验机：双击 [`open_operator_lan.bat`](../open_operator_lan.bat)（或 `open_operator.bat --host 0.0.0.0`）；被试显示器打开诱导页；
2. 监控端：浏览器打开 `http://<实验机IP>:8080/operator.html#setup`，确认 WS 状态灯转已连接；
3. 之后流程与本地模式完全一致（Setup → 诱导 → 标定 → 游戏）。

本机单屏回退：用原 [`open_operator.bat`](../open_operator.bat)（默认 `--host 127.0.0.1`）。

## 5. 验证清单（正式采集前必须全过）

| # | 测试 | 通过标准 |
|---|------|----------|
| V1 | 监控端连通性 | 第二台设备打开 operator.html，WS 状态显示已连接，能收到 `operator_hello` 回执 |
| V2 | 全流程冒烟 | 被试屏（本机）+ 操作台（远程）跑通一小段会话：setup → 诱导 ready → ≥1 轮标定 → 停止 |
| V3 | **试次中断网（关键）** | 标定试次进行中关闭监控端网络/浏览器：① 实验机试次**继续推进不卡死**；② 重连后状态自动恢复（`WsBridge` 设计有新连接重放 pending 的 prompt/stage/hud，但整断整连须实测确认） |
| V4 | 远程控制可用性 | 若监控端承担开始/continue/准入确认等控制：响应可用且延迟可接受；**建议控制操作仍留主机，远程端只读监控** |
| V5 | 回退演练 | `--host` 去掉（回到 127.0.0.1）本机单屏模式正常，与改造前行为一致 |

已知依赖点（审查结论，V3 重点覆盖）：会话启动依赖操作台在线（orchestrator 等待 `operator_hello`；流程中有"等待诱导页 ready"阻塞点，`orchestrator.py:552/801`）——**开始会话前监控端必须已连接**；试次中途断连的行为以 V3 实测为准。

## 6. 采集期运行守则

- 每日开机：先起后端 → 监控端连上并确认 V1 状态 → 再开始被试流程；
- 监控端断线：不打断实验，先跑完当前试次再重连；若 V3 发现断连会卡流程，则采集期降级为方案 A（单机双屏）；
- `smoke_operator_ws.py` 为本机工具，不能替代 V1–V5 的远程实测。
