# v3 信号质量门禁升级 + 基线"帽检"方案

日期：2026-08-24
状态：待确认（确认后按 Q1 → 回放校准 → Q2 → Q3 实施）

## 1. 背景：为什么需要这个功能

2026-08-24 真机 v3 测试（会话 `opsmoke_ws01_20260824_200329`，COM4，13 试次）出现
"左右一次都判不对"。离线诊断结论：

1. **模型从未输出 Left/Right**：13/13 试次 `p_three = [1.00, 0.00, 0.00]`，
   8 个左/右试次全部判成 Rest，0 次左右互换（排除 C3/C4 接反）。
2. **特征反向**：`mu_erd_contra` 全部为正值（+46% ~ +190%，均值 +104%；
   合格线 ≤ −15%），左右侧化不一致——任务窗伪迹比静息窗更大，ERD 成了伪迹随机数。
3. **物理解释（eeg.csv，滤波后 µV）**：
   - C3 带内近似死通道：CAR 后每试次 std 仅 1.7–5.4 µV；
   - 其余通道大幅伪迹：std 60–190 µV，全文件 |x| 最大 1132 µV、p99 = 737 µV；
   - 8 通道数百 µV 同步慢漂 → 参考电极（SRB2）/Bias 接触不良的共模特征；
   - FC4 部分时段钉死在常数（输入轨死）。
4. **门禁为什么没拦住（`signal_bad` 全场为 0）**：现有 `assess_eeg_window`
   只有下限检查（平线、低方差、低动态、饱和峰值、活跃通道数、通道失衡），
   而"高方差伪迹"恰好全部通过下限——**门禁有盲区，没有幅度上限检查**。
5. 问题具有持续性：184825 场全帽 ≤1.3 µV（全平），191820 场全通道 ±1100 µV 伪迹。

## 2. 判据来源：干净脑电的参考数值

取 OpenBMI 数据集（被试 1，右手运动想象试次，8 通道子集）按与 Cyton 管线等价的
预处理（0.5–45 Hz 带通 + 陷波 + 均值参考 + 降至 250 Hz）复算：

| 指标 | 干净数据（参考值） | 200329 坏数据 |
|---|---|---|
| 预处理后每通道 std | 3–5 µV | 60–190 µV（C3 去共模后 ≈2） |
| 预处理后幅度 p99 | < 15 µV | 500–900 µV |
| mu(8–13 Hz) 功率 | 50–160 µV² | 10⁶–10⁷ µV² |
| 波形形态 | 贴中线小碎波纹、通道间各动各的 | 数百 µV 同步大浪 |

在线采集比离线数据集略脏，判据留余量：**正常范围 ≈ std 3–30 µV、
幅度基本 < ±100 µV、通道间不同步**；< 1–2 µV 为死通道，> 60 µV 视为伪迹。

## 3. 修改内容

### Q1：`signal_quality.py` 新增三条检查（补上限盲区）

数据已是采集端滤波后的 µV（0.5–45 Hz + 陷波），直接在 3s 窗上计算：

| 新检查 | 判据（默认值，均可配） | 对应病灶 |
|---|---|---|
| `artifact` 大幅伪迹 | 中位通道 std > `max_median_std_uv` = 60 µV，或 ptp > `max_ptp_uv` = 400 µV | 肌电/运动/接触不良的大幅伪迹 |
| `dead_channel` 死通道 | 减去 8 通道均值（CAR）后，某通道 std < `min_car_std_uv` = 2 µV | 电极悬空：原始值只跟共模漂，去共模后无信号 |
| `common_mode` 共模同步 | var(8 通道均值) / 中位通道方差 > `max_common_mode_ratio` = 0.85 | 参考电极 / Bias 接触不良 |

实现约定：

- 原有 6 条下限检查全部保留，新检查按序追加；返回结构不变
  （`{ok, reason, metrics}`），`metrics` 增加 `common_mode_ratio`、
  `car_min_std_uv`、`dead_channel_idx` 等新量便于排查。
- `dead_channel` 只报通道**序号**，通道名由调用方（前端 `V3_CH`）映射，
  保持函数纯净。
- `SignalQualityConfig` 新增 4 个字段（上表阈值）；`v3_config.py` 透出对应
  `signal_*` 配置项。`v2_config.py` 无需改动（新字段有默认值）。

### Q2：接入 v3 三条路径

1. **实时帧路径**：`eeg_frame_publisher.py` 本就逐帧调用 `assess_eeg_window`，
   新判据自动生效（功率条变灰 + 提示行）。前端 `operator.js` 的
   `v3SignalNoteText` 增加原因→操作提示映射：
   - `artifact` → "大幅伪迹：减少移动、检查电极接触"
   - `dead_channel` → "通道 X 未接好：补胶/按紧"
   - `common_mode` → "参考电极接触不良：检查 SRB2/Bias"
2. **试次门路径**：`InferenceService.judge`（`inference_v2.py`）内部跑同一门禁，
   伪迹试次自动进入 `signal_bad`，从 acc/ERD/块统计剔除——**零改动自动生效**。
3. **新增基线"帽检"（本功能主角）**：`session_v3.py` 在开场 60s 基线结束时
   （现有 `v3_baseline_end` 处）把基线切成 3s 窗逐窗评估，汇总结论随现有
   `v3_baseline` 消息广播，并在操作台显示一行结论：
   - 坏窗占比 ≥ 50% → 红色"帽检未通过：大幅伪迹 N%、C3 死通道、参考电极接触不良——建议修好电极重跑"
   - 20%–50% → 黄色警告一行，继续会话
   - < 20% → 绿色"帽检通过（中位 std N µV）"
   - 只提示、不强制中止（操作者自行决定）；结论记入 events 与会话报告。
   - 基线同时是功率条的基线分母，帽检未通过时前端基线提示追加"基线可能无效"
     （占位逻辑已存在）。

### Q3：`v3_report.py` 新增"信号质量"小节

- 基线帽检结论（verdict + 坏窗占比 + 各原因计数 + 死通道列表）；
- 各原因被剔除试次的直方图（复用已有 `n_signal_bad`，补 reason 维度）。

## 6. 验收场景

- 电极全部接好 → 基线帽检绿灯，试次正常计分；
- 某一电极悬空（模拟：拔掉一路）→ 帽检报 `dead_channel X`，对应试次 `signal_bad` 剔除；
- 参考电极接触不良（模拟：大幅同步漂移回放）→ 帽检报 `common_mode`，功率条变灰；
- 咬牙/大幅运动 → 实时帧显示 `artifact` 提示，该试次不计统计。
