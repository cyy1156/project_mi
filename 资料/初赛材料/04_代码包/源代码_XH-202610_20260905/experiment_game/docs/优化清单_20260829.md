### 为什么这是问题

`run_v2_session` 一个人扛了：参数校验 → 设备连接 → LSL 建立 → 依赖装配 → trial 循环 → 状态机推进 → 推理 → 计分 → 广播 → 落盘 → 收尾。**任何一处改动都要先读懂 926 行**，且无法对单个环节做单元测试。

### 建议拆法（按「阶段」而非「功能」切）

```
run_v2_session()
  ├─ _setup_devices(cfg)      → 板卡/LSL/串口连接，返回 handle
  ├─ _build_deps(cfg, buf)    → OnlinePreprocessor + InferenceService 装配
  ├─ _run_trial_loop(...)     → 单个 trial：cue → MI → 计分 → 反馈
  ├─ _broadcast_progress(...) → WS 广播
  └─ _finalize(...)           → 落盘 + 收尾
```

**收益**：`_run_trial_loop` 这类函数可以被测试直接调用，不必跑完整会话。

> 注意：`session_v2.py` 1202 行、`session_v3.py` 968 行、`session_v4.py` 234 行 —— 三份实现**同时存在**，先确认 v2/v3 是否还在服役。若 v4 已替代前两者，删除比拆分收益大得多。

### 为什么必须改


最低要求：**补日志**。若要更严，可对落盘类操作（`live_capture.py:69`）改为向上传播。
