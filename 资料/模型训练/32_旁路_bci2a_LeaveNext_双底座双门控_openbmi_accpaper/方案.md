## 0. 一句话目标

A05 试点：**strict** 时线上贴底座；**force** 时三分类窗级爬升。  
本实验在 **A01–A09 齐全** 上回答：

1. **P0 · 底座**：同一门控下，**Shallow 单头** vs **E1f 四员融合读出** 谁更强？  
2. **P0 · 门控**：同一模型下，**strict** vs **force** 对爬坡与 PASS 率的影响？  
3. **P1 · FT 范围**：E1f 读出下，现行「**只 FT shallow、另三员冻结**」是否足够，还是需要「**四员各自 FT 再融合**」？

**不替代** fnz/syj 真机（实验 31）；本实验为 **同范式大样本仿真对照**。

## 1. 关于「是否微调其他三个成员」

### 1.1 现行实现（实验 31 / `pipeline.finetune`）

| 项 | 现状 |
|----|------|
| FT 写入 | 仅 **一对** `best_three.pt` + `best_task.pt` |
| 默认起点 | E1f 配置里的 **shallow fold0**（5090_alg_incr） |
| t_shallow / EEGNet / Conformer | **不参与梯度**；权重保持源域底座 |
| 线上读出 | `e1f_four_member.json`：**融合四员 three**（温度+权重）→ 因果平滑 → argmax / 多数票 |

因此线上默认 **不是**「四个成员一起微调」，而是「**只适配 shallow**，读出仍与冻结三员融合」。

### 1.2 本实验两种 E1f FT 口径（P1 对比）

| 代号 | FT 范围 | 读出融合输入 |
|------|---------|--------------|
| **`e1f_so`**（shallow-only） | 只训 shallow 的 three(+task) | `shallow_FT` + 三员**源域冻结** |
| **`e1f_all4`**（四员联合） | 四员 **各自独立** FT 自己的 three(+task) | 四员 **各自 FT 后** 再 Fuse |

```text
# e1f_so（现行 / P0 主表 E 臂）
p = Fuse(shallow_FT, t_shallow₀, eegnet₀, conformer₀) → 因果平滑 → argmax

# e1f_all4（P1 对比臂）
p = Fuse(shallow_FT, t_shallow_FT, eegnet_FT, conformer_FT) → 同套因果平滑 → argmax
```

**共同点（冻结，保证可比）：**

- 融合 **温度 / 权重** 固定取自 `e1f_four_member.json`（**不**在目标域重拟合）。  
- 因果平滑 lookback=2（与 F5 / Exp30 C 一致）。  
- Leave-Next 队列、replay、门控阈值、主指标完全相同。  
- 各员 FT **配方相同**（epoch / lr / batch / replay 比例与档位），**互不共享梯度**（不是单图联合反传，是四次独立 FT）。

**刻意不做（防混因子）：**

- 不把「四员联合反传 + 可学习融合头」放进本实验（另立号）。  
- 不在 all4 上重搜温度/权重（那是集成标定旁路，见 Exp28）。

### 1.3 Shallow 单头臂（P0 对照）

- FT：`5070_baseline` shallow task+three。  
- 评测：该头 `p_three` → **同一套因果平滑** → 窗级 argmax（无四员融合）。

### 1.4 `e1f_all4` 实现要点（待脚本）

| 步骤 | 约定 |
|------|------|
| 初始化 | 四员各自源域 `three_ckpt` / `task_ckpt`（见 `e1f_four_member.json`） |
| 每档 R≥1 | 对四员 **串行** 各跑一遍 `IncrementalFinetuner`（同 train/heldout/replay） |
| 门控输入 | 用 **融合后** heldout 三分类窗级算 `heldout_acc` / `max_class_frac` / `train_gap` / 三类覆盖（与线上读出一致；**不以单员 shallow 门控代替**） |
| 晋升 | strict/force 作用于 **整包四员 FT 产物**（同档全过或全留；不拆员晋升） |
| 落盘 | `…/e1f_all4_{strict\|force}/R*/members/{shallow,t_shallow,eegnet,conformer}/{best_three,best_task}.pt` + 融合评测 json |

> 现状管线尚无「四员串行 FT」一键入口；P1 需扩展 `run_subject_finetune` 或旁路脚本，**不阻塞 P0 开跑**。

## 2. 因子与臂（分阶段）

### 2.1 P0 · 主实验（先跑 · 登记主表）

| 因子 | 水平 | 代号 |
|------|------|------|
| **模型族 M** | 单头 ShallowFBCSP 3s | `shallow` |
| | E1f 读出 + **FT=so** | `e1f_so` |
| **门控 G** | FAIL 不晋升 | `strict` |
| | FAIL 仍晋升（F8） | `force` |

| 臂 | M | G | 登记列 |
|----|---|---|--------|
| A | shallow | strict | `S-st` |
| B | shallow | force | `S-fo` |
| C | e1f_so | strict | `E-so-st` |
| D | e1f_so | force | `E-so-fo` |

**主对比：** A vs C；B vs D。  
**副对比：** A vs B；C vs D。

### 2.2 P1 · FT 范围对比（E1f 内 · 登记对照表）

在 **E1f 融合读出** 上增加因子 **F ∈ {so, all4}**，门控仍 ×2：

| 臂 | F | G | 登记列 | 说明 |
|----|---|---|--------|------|
| C | so | strict | `E-so-st` | 与 P0 共用，不重跑 |
| D | so | force | `E-so-fo` | 与 P0 共用 |
| E | all4 | strict | `E-a4-st` | **新增** |
| F | all4 | force | `E-a4-fo` | **新增** |

**P1 主对比（同门控）：** C vs E（strict）；D vs F（force）。  
**决策问句：** all4 相对 so 的 Δ三分类窗级是否稳定为正、且值得约 **×4 FT 算力**。

**开跑顺序建议：**

1. 先跑完 P0（A–D）→ 填主表。  
2. 若 P0 显示 **force 明显优于 strict**（A05 已暗示），P1 可 **优先只跑臂 F（all4×force）**，与 D 对照；strict 臂 E 作补全。  
3. 若算力充足，E/F 与 C/D 一次齐跑。

### 2.3 臂总览

```text
P0:  shallow × {strict, force}     →  A, B
     e1f_so × {strict, force}      →  C, D
P1:  e1f_all4 × {strict, force}    →  E, F   （相对 C, D）
```

## 5. 发布门控

与 `pipeline.finetune.evaluate_release_gate` 一致（**all4 在融合概率上算**）：

| 检查 | 阈值 |
|------|------|
| `heldout_acc` | ≥ 0.40 |
| `max_class_frac` | < 0.60 |
| `train_gap` | train−heldout < 0.35 |
| `three_classes_pred` | Rest/L/R 均有预测 |

- **strict**：FAIL → 不替换本臂 current。  
- **force**：仍晋升；`release_gate.json` 落盘审计。  
- 各臂独立权重链，互不污染。

## 6. 指标（冻结）

### 6.1 主决策指标

**三分类窗级准确率（含 Rest）**  
`pred == y_three`，`y ∈ {Rest, Left, Right}`；读出见 §1.2 / §1.3。  
**不以「仅 L/R」作主决策**（L/R 仅辅表）。

### 6.2 辅指标

| 指标 | 用途 |
|------|------|
| 窗级 L/R acc | 诊断 Rest 投机 |
| 试次多数票（F5） | 对齐线上计分 |
| 门控 PASS/FAIL、`train_gap` | 策略审计 |
| 底座零样本 @ 同 eval | 对照列 |
| （P1）单员 heldout 三分类 | 诊断哪一员拖后腿 / 过拟合 |

## 7. 单臂流程

```text
current ← 底座（so：shallow 一对；all4：四员源域包）
for R in 0..5:
  if R == 0:
    报 Fuse/单头(current) @ run3
  else:
    if so:   FT(shallow only)
    if all4: for m in {shallow,t_shallow,eegnet,conformer}: FT(m)
    gate ← release_gate(融合或单头 three @ heldout)
    if G==force or gate.pass: current ← 本档 FT 产物
    报 读出 @ eval（主：三分类窗级含 Rest）
```

## 10. 决策规则

### 10.1 P0（底座 × 门控）

| 观察 | 倾向 |
|------|------|
| force 下 e1f_so ≫ shallow | 保留 E1f 融合读出 + 可强制晋升 |
| strict 下两模型均贴底座 | 门控过严；默认 force+告警 |
| shallow force ≈ e1f_so force | 融合增益有限，主收益来自晋升 |
| 三分类↑ 但 L/R↓ | 记 Rest 投机；主决策仍用三分类窗级 |

### 10.2 P1（FT 范围）

| 观察 | 倾向 |
|------|------|
| all4 − so ≥ **+2 pp**（R5 九人均值）且多数被试同向 | **值得**上四员 FT；改线上管线 / 另开部署任务 |
| \|all4 − so\| < 2 pp 或异号 | **维持**现行 so；all4 不算力优先 |
| all4 仅 force 升、strict 更差 | 过拟合风险；门控/早停需另调，不默认上 all4 |
| all4 三分类↑ 但单员辅表某一员塌缩 | 融合掩盖失败员；记录后考虑只 FT 子集（另旁路） |

**线上默认变更门槛：** P1 九人齐全 + force 下 all4 相对 so 稳定增益 + 算力可接受（约 4× FT 时间）。
