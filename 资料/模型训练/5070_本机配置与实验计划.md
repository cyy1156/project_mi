| 项 | 实测 | 对实验的含义 |

## 2. 三机位分工（建议）

| 机位 | 角色 | 默认超参 | 结果口径 |
|------|------|----------|----------|
| **5070（本机）** | **正式出数 / 日常迭代** | batch **128/256** · workers **0～2** · AMP · Fast | 新正式表以本机为准 |

## 3. 推荐训练配方（5070 默认）

对齐现有 `5060_mask_future_dual_expert_accpaper/shared_hparams.py`，只做「能稳跑」方向的微调：

| 超参 | 5070 建议 | 说明 |
|------|-----------|------|
| `batch_train` / `batch_eval` | **128 / 256** | 8GB VRAM 安全默认；OOM 再降到 96/192，**不要默认 256/512** |
| `num_workers` | **0**（稳）→ 试探 **2** | Windows + npy memmap；不稳定立刻回 0 |
| `pin_memory` | workers=0 时 **False** | 与 5060 包一致 |
| `use_amp` | **True** | Fast 正式模式 |
| `cudnn_benchmark` | 冒烟 **False**；过夜可试 **True** | 与 5060 低内存默认一致偏稳 |
| `torch_num_threads` | **4～8**（本机 24 逻辑核） | 勿开到顶，留余量给系统 / 看门狗 |
| `max_folds` | 门控 **1** → 通过后再 **5（`--max-folds 0`）** | commit 已够，仍建议先 fold0 |
| 内存看门狗 | **必开**（方案 16/17 脚本） | 防 Event 2004；`commit_limit≈64G` 下允许 pagefile 增长 |

**OOM / 卡死降级顺序**：关 PyCharm / 浏览器 → `batch_train=96` → `num_workers=0` → `sigreg_slices` 暂降（仅调试）→ 回 5090 跑该臂。

## 5. 分阶段实验计划

### 阶段 0 · 基建（0.5～1 天）

1. 修好 `cyy`（或新建 `cyy312`）+ PyTorch CUDA。  
2. 同步 / 生成 `openbmi_2s_hop100` 与 `openbmi_2s_hop100_pf1000`。  
3. 从 `5060_mask_future_dual_expert_accpaper` **浅拷贝**出 `5070_mask_future_dual_expert_accpaper`：  
   - 改 `TRAIN_DEVICE_LABEL` / `OUT_ROOT_TAG` / `protocol` 中的 `device=5070`  
   - 默认超参按 §3  
4. 跑 `_smoke_local.py` + `run_arm.py --arm A0 --max-folds 1`。

**门控**：冒烟通过且 fold0 不触顶 commit。

### 阶段 1 · 机位校准（1～2 天）

目的：证明 5070 管线 ≡ 旧 5060 正式量级（允许 Fast 小波动）。

| 臂 | 对照锚点（旧 5060 五折） | 5070 动作 |
|----|--------------------------|-----------|
| A0_ref | Three ≈ **0.5403±0.0256** | 五折或至少 fold0→再五折 |
| A0 | ≈ **0.5342±0.0242** | 同上 |
| P2 | ≈ **0.5707±0.0112** | 主表校准臂 |

**门控**：|Δ mean Acc_paper| ≲ **0.01**（相对旧 5060 同臂）；失败先查数据 / seed / 早停，不急着改模型。

登记建议目录：

- 文档：`资料/模型训练/17_5070_旁路_掩码未来双专家门控_openbmi_accpaper/`  
- 代码：`code/train_lab/src/step/5070_mask_future_dual_expert_accpaper/`  
- out：`code/train_lab/out/5070_mask_future_dual_expert_accpaper/`  
- runs：`资料/模型训练/runs/5070_mask_future_dual_expert/`

### 阶段 2 · 方案 17 主线复现 / 补洞（按需）

旧 5060 / 5090 主线与 U 已有五折结果。5070 上建议：

1. **不必重跑整条历史链**（除非要换正式机位标签）。  
2. 优先跑 **尚未定论或要继续迭代的臂**（新结构、新损失、新数据切片）。  
3. 需要全消融时：`chain_all.py --full-chain` + `run_gate_chain_guarded.ps1`（五折）。  
4. U 系列：`chain_u_all.py` / `run_u_chain_guarded.ps1`。

### 阶段 3 · 方案 16（复合损失）在 5070 上的位置

| | 建议 |
|--|------|
| 角色 | 仍旁路；冲 Task 0.75 / Three 0.60 |

| 与 5090 | 大扫参 / 过夜全链可仍丢 5090 |

### 阶段 4 · 下一方法（正式迭代窗口）

机位校准通过后，新方法默认只在 **5070 包**立项，例如：

- 在 P2 / U1 上继续结构或损失改动（新方案号 **18+**）  
- 伪在线 / 游戏零样本权重迁移（沿用 Acc_paper 口径）

## 7. 风险与禁止项

| 风险 | 处理 |
|------|------|
| 8GB VRAM OOM | 降 batch；确认 AMP 开；勿同时开游戏/大浏览器占显存 |
| 16GB RAM + pack 顶 commit | 必开 mem_guard；少开 IDE；pagefile 保持 D: 固定大文件 |
| Python 3.13 无匹配 torch 轮子 | 新建 3.11/3.12 环境，勿硬装失败轮子 |
| 与 5060 数字混表 | 表头标明 **device=5070**；旧 5060 表只读 |
| 误 `push` 空仓 / 覆盖 out | out 大文件跟 `.gitignore`；权重不同步 git |

**禁止**：把本机结果写进旧「5060 十一模型正式表」而不改机位标签；默认 batch 直接抄 5090；关掉 pagefile「省磁盘」。
