> 角色：在 **纯 Cue MI、无神经反馈** 的 BCI2a 上，检验 Exp27 统一 FT 策略是否普适；**不替代** fnz 真机结论。

## 0. 一句话目标

fnz 窗数少（~200–350），难以区分「策略不行」与「样本太少」。  
实验 29 在 **BCI2a Training（T.mat）** 上，用 **9 被试 × 全部 6 run × 大窗数**，镜像 Exp27 离线 FT，回答：

1. 大样本 + **与 OpenBMI/fnz 同范式**（Cue 后 0–4 s）下，B2 是否稳定？  
2. 单伪 session FT（Track S）vs 合并 FT（Track M）孰优？  
3. **Run Ramp（主）**：固定 B2，逐 run 累积 FT，**在线 trial acc 在第几「数据轮」达到 ≥60%**？  
4. fnz 若仍差于 BCI2a → 更指向 **个体/电极/采集**，而非策略或 n alone。

**执行优先级：** Run Ramp 主实验（54 runs）→ 视结果决定是否开 epoch 子扫 / 全网格 144 runs。

## 1. 为什么用 BCI2a（不用 Stieger 反馈段）

| 数据源 | Task 窗 | 与 fnz v3 / OpenBMI 底座 |
|--------|---------|--------------------------|
| Stieger `stieger_3s_hop100` | 反馈段 `[fb0,fb1)` | ❌ 闭环神经反馈 MI |
| **BCI2a T.mat** | **Cue 后 0–4 s** | ✅ 纯 Cue MI，与 OpenBMI 一致 |
| BCI2a E.gdf | 评估 session | ❌ 本实验 **不用**（格式 .gdf，未接入） |

**数据文件：仅用 `A01T.mat` … `A09T.mat`（Training）；忽略 `A*E.gdf`。**

## 2. 数据与预处理

### 2.1 原始结构（BCI IV 2a · T）

| 项 | 内容 |
|----|------|
| 被试 | **A01–A09**（9 人） |
| 文件 | 每人 1 个 `AxxT.mat` |
| 带标签 run | **6 个**（每人全部用完；A01 等多为 run3–8，A04 为 run1–6） |
| 每 run | 48 trials（左/右手；脚/舌已丢弃） |
| 通道 | 22 导 → 8 导子集，顺序与 OpenBMI 相同 |

### 2.2 伪 session（同日多 run → 模拟多 session FT）

官方 T 为**同日**连续 run；用每人 **最后 6 个带标签 run** 顺序配成 3 对（A01 等为 run3–8，A04 为 run1–6）：

| 伪 session | run 位置（每人最后 6 run 内） |
|------------|------------------------------|
| **S1** | 第 1–2 run |
| **S2** | 第 3–4 run |
| **S3** | 第 5–6 run |

> **局限**：测的是「同日内 run 间泛化」，不是 Stieger/fnz 式跨日 session；但 **范式与窗长与 OpenBMI 3s 完全一致**。

### 2.3 切窗协议

| 段 | 定义 |
|----|------|
| **Task** | Cue 后 **0–4 s** → 3s / hop 100ms → `(8,750)` |
| **Rest** | Cue **前 4 s** → 同上 |
| 滤波 | CAR · 8–30 Hz · 窗内 z-score |
| `subjects` 键 | `A01|run3|S1`（被试 \| run \| 伪 session） |

### 2.4 输出

```text
code/preprocess_lab/out/bci2a_3s_hop100/
├── manifest.json
├── shards/A01_run3/...
└── bci2a_{X,y_task,y_three,subjects,trial_id}.npy
```

### 2.5 生成命令

```bash
cd code/preprocess_lab
python -m src.datasets.bci2a.batch_3s_hop100 --glob "D:/MI/DATA/bci2a/A0*T.mat"
# 冒烟：--limit 1
```

配置：`config/bci2a_3s_hop100.yaml`

## 3. 实验设计

### 3.1 子实验总览

| 子实验 | 目的 | 规模 | 优先级 |
|--------|------|------|--------|
| **§3.5 Run Ramp** | 用尽 6 run · 在线 trial acc 何时 ≥60% | 9×6 = **54**（固定 B2） | **P0 · 先做** |
| §3.2 双轨网格 | Replay 配方对比（镜像 Exp27） | 9×2×8 = **144** | P1 · 可选 |
| §3.5.4 epoch 子扫 | R5 仍 <60% 时排查训练轮数 | 9×4 = **36** | 条件触发 |

---

### 3.2 双轨网格（镜像 Exp27 · 可选）

| Track | FT 训练伪 session | 在线评估伪 session |
|-------|-------------------|-------------------|
| **S** | **S1**（第 1–2 run） | **S2**（第 3–4 run） |
| **M** | **S1 + S2**（第 1–4 run） | **S3**（第 5–6 run） |

**9 被试 × 2 track × 8 arms = 144 runs**

#### 网格臂

A0 · B1–B4 · E1 · F-A0 · F-B2（F 臂：下采样至 ~310 窗，对照 fnz 量级）

---

### 3.3 划分（双轨与 Ramp 共用）

| 项 | 取值 |
|----|------|
| FT 池内 train / heldout | **Cue 级 70 / 30** · `seed=42` |
| `split_id` | `{A01}|{run}|trial_id` |
| **在线评估** | **整 run / 整伪 session 不参与 train/heldout**（forward only） |
| 投票 | 试次内窗 **多数投票** → **trial acc**（three 头） |

---

### 3.4 固定 FT 策略（同 Exp27）

| 项 | 取值 |
|----|------|
| 底座 | `run_20260822_094942` · `best_{task,three}.pt` |
| Replay | **T0-36** · `openbmi_3s_hop100_t0` · **ratio=0.10** |
| Ramp / 默认冠军臂 | **B2**（全模型 · **5 epoch**） |
| 超参 | `lr=1e-4` · `wd=1e-4` · `batch=32` · `seed=42` |
| 每轮 FT 起点 | **始终从同一 OpenBMI 底座重训**（不链式叠 checkpoint，对齐 fnz session 间离线 FT） |

---

### 3.5 Run Ramp 子实验（用尽 6 run · 冲 60% 在线 trial acc）

#### 3.5.1 术语

| 术语 | 定义 |
|------|------|
| **数据轮 R** | FT 训练池包含该被试按序的前 **R** 个带标签 run（R=1…5）；R=0 表示仅底座、不 FT |
| **epoch** | 单次 FT 的训练轮数，Ramp **默认 5**（与 Exp27 一致）；与「数据轮 R」不同 |
| **在线** | 在 **尚未参与 FT 的 run** 上评估（整 run forward） |

#### 3.5.2 主协议：Leave-Next-Run（P0）

对每个被试 A01–A09，run 按 mat 内顺序编号为 run₁…run₆：

| 数据轮 R | FT 训练 run | 在线评估 run | 累计 FT 窗（约） | 类比 fnz |
|----------|-------------|--------------|------------------|----------|
| **R0** | 无（仅底座） | run₂ | 0 | 零样本 → 下一场 |
| **R1** | run₁ | run₂ | ~350 | — |
| **R2** | run₁+₂ | run₃ | ~700 | ≈ ws01 单独 FT 窗量级 |
| **R3** | run₁…₃ | run₄ | ~1050 | — |
| **R4** | run₁…₄ | run₅ | ~1400 | ≈ ws01+ws02 合并 |
| **R5** | run₁…₅ | run₆ | ~1750 | 用尽前 5 run |

- **策略固定 B2**；每 R 独立从底座重训。  
- **主表指标**：评估 run 上 **trial acc**（three 头，试次多数投票）。  
- **规模**：9 被试 × 6 点（R0–R5）= **54 runs**。

**核心问题：** 队列平均 trial acc 在第几轮 R **首次 ≥60%**？每人分别在第几轮达到（若达不到，记峰值 R 与 acc）？

#### 3.5.3 辅协议：Prefix-Train → Final-Run₆

固定 **run₆** 为终局在线目标，训练前缀逐渐变长：

| 数据轮 R | FT 训练 run | 在线评估 |
|----------|-------------|----------|
| R1 | run₁ | run₆ |
| R2 | run₁+₂ | run₆ |
| … | … | run₆ |
| **R5** | run₁…₅ | run₆ |

- 测 **同日最远 run 泛化**（比 Leave-Next 更难）。  
- 若 Leave-Next 已 ≥60% 而 Final-run₆ 仍低 → 支持 **run 间漂移** 显著。  
- **规模**：9×5 = **45 runs**（可与 Ramp 主表合并报告）。

#### 3.5.4 F 窗数对照（fnz 量级）

在选定 R 上，将 FT 池 **下采样至 ~310 窗**（与 fnz ws01 同量级），仍用 B2：

| 对照 | 做法 |
|------|------|
| **F@R2** | ~310 窗（≈ fnz 单 session）· B2 |
| **F@R4** | ~310 窗（从 R4 池抽）· B2 |
| 全量 R4 | R4 池全窗 · B2 |

读数：F@R2 ≈ fnz 且全量 R4 远高于 F@R4 → **样本量** 主因；F 与全量均低 → **域移/策略** 主因。

#### 3.5.5 条件触发：epoch 子扫

**触发条件：** Leave-Next **R5** 队列平均 trial acc 仍 **<55%**，或个体峰值明显随 R 上升未饱和。

在 **R5（run₁…₅ FT → eval run₆）** 固定数据，只改 epoch：

| 臂 | epoch |
|----|-------|
| E3 | 3 |
| E5 | 5（默认） |
| E10 | 10 |
| E15 | 15 |

规模：9×4 = **36 runs**（仅条件满足时执行）。

---

### 3.6 task 串行门控对照（Exp27 延伸 · 可选）

在 Leave-Next **关键点 R0 / R2 / R4 / R5** 上，对匹配 **task 头**（B2 · T0 task replay 0.10）做 `task_p_on` 扫描，对比纯 three。

| 项 | 取值 |
|----|------|
| 扫描 | `task_p_on ∈ {0, 0.3, 0.5, 0.6, 0.7, 0.8}` |
| 指标 | 评估 run **试次级多数票 acc** |
| 规模 | 9×4 = **36 点**（R>0 每点 three+task 各 FT 一次） |
| 脚本 | `experiment_game/tools/exp29_bci2a_serial_gating.py` |

**读数：** 若高 acc 段（R4/R5）队列 mean Δ < +2pp → 支持 Exp27「默认 `task_p_on=0`」；局部被试（类偏 / 低 acc）可有 +3~7pp。

## 4. 主指标与 60% 判定

### 4.1 指标优先级

| 优先级 | 指标 | 说明 |
|--------|------|------|
| **P0** | **在线 trial acc**（three 头） | 评估 run 上，试次内窗多数投票 |
| P1 | 三类试次均有预测 | 防类塌缩（如 Right→0） |
| P2 | heldout three acc | 仅 FT 池内监控过拟合，**不作部署选型主依据** |
| 辅 | BalAcc / 每类 recall | 与 trial acc 同表，避免 60% 来自偏类 |

### 4.2 60% 判定规则（预注册）

| 层级 | 规则 |
|------|------|
| **被试级** | 该被试在某一 R 的 P0 trial acc **≥ 0.60** |
| **队列级（主结论）** | 9 人 **平均** P0 trial acc **≥ 0.60** |
| **稳健性（辅）** | **≥6/9** 被试个体 trial acc ≥ 0.60 |

报告：**首次达到队列均值 ≥60% 的数据轮 R**；若 R5 仍未达到，报告峰值与「未达标」结论，不强行外推 fnz。

### 4.3 读数预期

```text
在线 trial acc
  60% ───────────────────────────── 目标线（P0）
  45% ──── fnz Exp27 在线约在此带
  40% ──── heldout 常见带（勿当真机）
       R0   R1   R2   R3   R4   R5
            累计 FT run 数 →
```

| 现象 | 解读 |
|------|------|
| R2–R3 即 ≥60% | fnz 主要差在 **n 小**（~200 窗 vs ~700+） |
| R5 才 ≥60% | 需 **多 run 合并**；fnz 继续采 session 有价值 |
| R5 + epoch10 仍 <55% | BCI2a 上策略/域上限；fnz 60% 需更多域适配 |
| Leave-Next 高、Final-run₆ 低 | **run 间漂移** 大；跨日 fnz 会更难 |

### 4.4 与 fnz / Exp27 对照锚点

- fnz Track S 在线 ~45%（B2）；窗 ~208（ws01）。  
- fnz Track M 合并窗 ~338。  
- BCI2a R2 ≈ 700 窗、R4 ≈ 1400 窗，用于判断「同样策略、多几倍窗」能否到 60%。

## 5. 边界

- **不用 E.gdf**；不混 Stieger/BCI2a 进 replay 池。  
- BCI2a 为 **同日 6 run**，非 fnz **跨日 ws**；Ramp 结论外推 fnz 时必须注明。  
- 60% 为 **探索目标**，非部署承诺；如实报告未达标峰值。  
- 每轮 FT **从同一底座重训**（非链式增量）；链式 FT 另开实验。  
- Stieger Cue 预处理（`stieger_cue_3s_hop100`）保留为备选，**非 Exp29 主线**。
