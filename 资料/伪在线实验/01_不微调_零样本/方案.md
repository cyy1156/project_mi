## 0. 一句话目标

把 **sub02 / sub03** 两场真实采集会话各自切成 **MI 段与 REST 段**，在 **同被试内** 严格对齐标签后拼成 **一段连续评测数据**，再按主线伪在线方式做 **全量 2 s 窗 / 100 ms 步长** 滑窗推理；**两人分开测试**；**不微调游戏数据**，只加载 **03 Acc_paper 重训权重**（`*_2s_hop100_balbatch_accpaper`），评测 Top5 模型在自采数据上的**零样本**伪在线表现。

## 3. 切段规则（MI / REST）

对每个 acquire、未 reject 的 `trial_id`：

| 段类型 | 时间区间 | `y_three` | `y_task` | 附加元数据（必留） |
|--------|----------|-----------|----------|-------------------|
| **MI** | `[t_mi_start, t_mi_end)` | 1 或 2（来自 `mi_start.label`） | **1**（Task） | `subject_id, trial_id, seg=mi, t0_lsl, t1_lsl` |
| **REST** | `[t_rest_start, t_rest_end)` | **0** | **0** | `subject_id, trial_id, seg=rest, t0_lsl, t1_lsl` |

硬约束：

1. **标签一致性**：`mi` 段禁止出现 label∉{1,2}；`rest` 段必须 label=0。  
2. **被试一致性**：段 meta 的 `subject_id` 必须等于 `session.meta.json` 的 `subject_id`。  
3. **时长**：目标 4.0 s @ 250 Hz → 约 1000 点；不足 2 s（滑窗最小窗长）的残段 **丢弃该段**，禁止 padding。  
4. **通道**：映射并重排为训练序  
   `C3, C4, Cz, CP3, CP4, CPz, FC3, FC4`  
   （与 `experiment_game/offline/channels.py` / Phase4 一致）。

输出物（本臂）：

```text
资料/伪在线实验/01_不微调_零样本/out/<session_id>/
```

## 4. 同被试连续评测流构造

### 4.1 原则

- **只在同一 `subject_id` 内拼接**；sub02 与 sub03 **各一份**连续流。  
- 「两个段」= 该被试的 **全部合法 MI 段 + 全部合法 REST 段**。  
- 拼接后得到每人一条 **逻辑连续 EEG**（伪在线滑窗的载体），不是跨人 merged。

### 4.2 拼接顺序（冻结）

按 **acquire 的 `trial_id` 升序**，每个 trial 内顺序为：

```text
… → MI(trial_k) → REST(trial_k) → MI(trial_k+1) → REST(trial_k+1) → …
```

理由：接近真实会话时间线（先想象后静息），便于日后对照真缓冲回放；且每个边界两侧标签明确。

可选附录（不进主表）：「先全部 MI 再全部 REST」拼接，用于检查拼接顺序是否敏感。

### 4.3 边界与标签轨

连续流上并行维护：

| 轨 | 含义 |
|----|------|
| `x[t]` | 拼接后的多通道 EEG |
| `y_three[t]` | 该采样点所属段标签（段内常数） |
| `y_task[t]` | 0/1 |
| `trial_id[t]` / `seg[t]` | 溯源 |
| `is_boundary[t]` | 段接缝标记（可选） |

**禁止**在接缝处伪造平滑或重叠混合标签。

### 4.4 预处理落点（与离线可比）

建议在 **段级或连续流级** 统一执行（实施时二选一写死，主表只认一种）：

```text
通道重排 → CAR → 50 Hz notch → 8–30 Hz 带通
→（滑窗取出后）与 Phase4/训练一致的窗内基线/标准化策略
→ 送入模型 (1, 8, 500)
```

若与 BCI2a hop100 训练预处理有差异，须在结果 MD 头标注 `preprocess=game_phase4_like | bci2a_hop100_like`，并先做 **固定 2 s 冒烟** 再出主表。

## 5. 伪在线滑窗（全量 · 2s / 100ms）

### 5.1 参数（与主线一致）

| 项 | 值 |
|----|-----|
| \(T_w\) | **2 s** → **500** 点 @ 250 Hz |
| hop | **100 ms** → **25** 点 |
| \(f_u\) | 10 Hz |
| 形状 | `(N, 1, 8, 500)` |

窗数（对长度为 \(T\) 秒的**单一标签合法区**）：

\[
N_w = 1 + \frac{T - 2}{0.1}\quad (T\ge 2)
\]

满 4 s 段理论 \(N_w=21\)。

### 5.2 「全量」合法窗定义（冻结 · 防标签污染）

在连续评测流上按 100 ms 步进扫描，但 **仅当** 满足：

1. 窗覆盖的 500 点 **全部落在同一原始段内**（同一 `trial_id` + 同一 `seg∈{mi,rest}`）；  
2. 该段标签在窗内 **恒定**；  

该窗才进入测试集。

**跨 MI|REST 接缝、跨 trial 接缝的窗一律丢弃**（不 padding、不取众数标签凑窗）。

> 说明：拼接是为了得到「每人一份完整可滑窗语料」；伪在线有效窗仍限制在真实 MI/REST 段内部，等价于对全量段做段内滑窗后汇入该被试测试池——与「在线缓冲只在当前 4 s 任务态出窗」一致。

### 5.3 回放方式

| 项 | 约定 |
|----|------|
| 顺序 | 按连续流时间 / 窗起点 **严格有序**（可记录顺序；评估可向量化） |
| 缓存 | **关闭** RAP 特征缓存 |
| OTTA | **关闭** |
| 梯度 | `torch.no_grad()` |
| 被试 | 跑完 sub02 全部分数再跑 sub03；结果目录分被试 |

## 7. 指标口径（对齐现行 03 Acc_paper）

窗级预测集合 = §5.2 合法窗全量。  
真值 = 该窗所属段标签映射到 Task / Three。  
段 = 一条 MI 或一条 REST（`trial_id+seg`），对应 03 的 trial 聚合单元。

### 7.1 Task（二类：Rest=0 / Task=1）

| 指标 | 说明 | 地位 |
|------|------|------|

| **BalAcc_maj（段级）** | 段内窗众数 → 段预测；并列最高票计错 | **附报** |
| 窗级 BalAcc / Spec / Rec / F1 / Acc | 与 01 窗级字段同形 | **附报**（对照迁移，不夺本方案冠） |

报：**每人 × 每模型** 的五折 **mean±std**。

### 7.2 Three（三类：0/1/2）

| 指标 | 说明 | 地位 |
|------|------|------|
| **Acc_paper（段级）** | 同上 | **主指标** |
| **BalAcc_maj（段级）** / F1-macro（众数） | 段级聚合 | **附报** |
| 窗级 BalAcc / F1-macro / Rec idle·left·right | 窗级 | **附报** |

### 7.3 明确不对齐项（避免误读）

| 项 | 说明 |
|----|------|
| 训练域 | 权重来自 **BCI2a · Acc_paper 重训**；测试为 **自采游戏** → 零样本迁移 |
